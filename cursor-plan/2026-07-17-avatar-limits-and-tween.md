# 数字人回复限制与动作补间分析

## 目标

厘清两件事：

1. 回复长度限制应只约束台词文字，不应约束动作时间线。
2. 连续动作之间是否需要、以及如何需要动画补间。

## 现状

### 文字限制

- `MAX_REPLY_LENGTH = 150` 只作用于 `speech.text` 的截断。
- `timeline` 另有独立约束：最多 6 个动作、白名单、相对时间 `at ∈ [0, 0.95]`。
- 所以代码层面，动作本来就不占用 150 字额度；但系统提示词仍把“回答”和“动作编排”写在同一套规则里，模型容易误以为总输出要很短。

### 动作切换

- 前端按音频总时长把 `at` 映射成定时器，到点调用 `playReplyMotion`。
- 切换前会先 `stopActiveMotion()`，再播新动作。
- MotionEngine 配置了 `gestureFadeIn: 350`、`gestureFadeOut: 350`、`stopFade: 100`。
- 问题：主动打断时用的是更快的 `stopFade=100ms`，连续手势舞时容易出现“收得太快 → 再起下一个”，视觉上偏硬切。

## 结论

### 1. 限制边界

| 维度 | 应限制对象 | 当前是否正确 | 建议 |
|---|---|---|---|
| 字数 | 仅 `speech.text` | 代码正确，提示词易误解 | 提示词明确“150 字只限台词” |
| 动作数量 | `timeline` 条数 | 已有 `MAX_MOTIONS=6` | 保留独立上限，与字数解耦 |
| 计费/延迟 | TTS 文本长度、动作切换开销 | 间接受台词长度影响 | 继续用 TTS 代理的文本上限 |

### 2. 补间是否必要

需要，但分两层：

1. **引擎层补间（已有，需调参）**  
   TalkingHead / MotionEngine 的 fade in/out 就是骨骼/表情插值。连续动作应优先用更长的淡入淡出，而不是打断时的快速 `stopFade`。

2. **时间线层留白（建议新增）**  
   仅有 `at` 不够。两个动作若间隔小于 fade 时长，会互相打断。应至少保证：
   - 相邻动作间隔 ≥ fadeIn + fadeOut（约 600–800ms）
   - 或协议增加可选 `holdMs` / `transitionMs`
   - 前端调度时若间隔过短，自动拉开或合并

### 3. 不建议一上来做的事

- 不让 LLM 输出任意骨骼关键帧或自定义缓动曲线。
- 不把补间做成独立 `timeline` 事件类型（首版），除非明确要“停顿/hold”。
- 不把动作数量并进字数限制。

## 推荐方案

### 短期（低成本，本次实施）

1. 提示词写明：`150` 只约束 `speech.text`；动作数量按台词长度分配（约每 15 个汉字最多 1 个动作），相邻 `at` 留足间隔。
2. 动作间切换交给 MotionEngine 自身的打断淡出，`stopFade` 从 100ms 提到 400ms，形成近似交叉过渡；快速硬停只保留给用户主动停止。
3. 前端调度加最小间隔保护（2.5 秒）：相邻动作换算后的间隔不足时直接丢弃后一个，宁少勿挤。
4. CosyVoice 播报结束后给最后一个动作约 1.2 秒收尾再清理；新提问或手动停止仍立即硬停。

### 中期（协议扩展）

```json
{
  "type": "avatar_response",
  "version": 1,
  "speech": { "text": "...", "language": "zh-CN" },
  "timeline": [
    { "type": "motion", "name": "wave_right", "at": 0.1, "transitionMs": 400 },
    { "type": "motion", "name": "thumbs_up", "at": 0.45, "holdMs": 600 }
  ]
}
```

- `transitionMs`：切入该动作的淡入时长。
- `holdMs`：可选，表示希望保持到下一段的最短时间。
- 仍不把这些字段算进字数限制。

## 风险

- CosyVoice 无词级时间戳，补间再好也只能对齐到相对位置。
- fade 过长会吃掉短台词中间的动作窗口。
- 模型若把动作名写进台词，仍可能显得啰嗦；那是文案问题，不是字数上限问题。

## 验收标准

- 字数上限语义上、实现上、提示词上均只约束 `speech.text`。
- 手势舞相邻动作有可感知的过渡，无明显硬切。
- 未知 timeline 字段被忽略，不影响播报。
