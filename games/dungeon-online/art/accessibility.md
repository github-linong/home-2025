## 0. 文档定位与分级模型
- 本档是 art-bible §10「可访问性」的**分级展开**：把"Lean 最低交付硬底线"拆成三档可执行清单。
- 三级模型（包含关系 **Basic ⊆ Standard ⊆ Comprehensive**）：
  - **Basic（硬底线 / 不可砍）**：art-bible §10「Lean 最低交付」——缺一项即违反 P3 可读性与色盲安全纪律。
  - **Standard（MVP 目标档）**：本作在 Lean 预算下交付的可访问性集合（art-bible §10 目标定为 Standard；**用户拍板 MVP 即此档**）。
  - **Comprehensive（升级钩子）**：资源/时间允许时的增强，**留作后续里程碑**，不阻塞 MVP。
- 实现方：art-director 出**美术规格与判据**；engineering-lead 出**工程实现**。下表标注"归属（美术/工程）"与"实现成本（低/中/高）"。

## 2. 三档核心差异摘要
- **Basic**：仅保 P3 可读性与色盲安全底线（调色板 + 对比度 + 三重编码 + 静态预警 + 重映射 + 环形进度）。美术零额外资产，工程最小——是 Lean 不可砍红线。
- **Standard（MVP 交付）**：在 Basic 上加"可切换"层——色盲开关、字体缩放、减弱动效、静/动 telegraph 切换、事件文本、文字图标冗余。美术增量 = 图标集 + 斜纹图案 + 静态环形资产；工程增量 = 设置菜单 + 状态持久化。
- **Comprehensive**：把"可用"推向"舒适"——字幕/音频冗余、高级色盲自定义、自由缩放、全键盘、音频可视化、一键最大可访问性预设。增量主要在工程 + 美术扩展资产，**留作后续里程碑**。

## 3. 与 P3 不等式的耦合
- 静态 telegraph（#4）是不等式 `前摇 ≥ max(0.6s, RTT+K)` 的美术载体；帧预算见 telegraph-inequality-cost.md。
- 动态/静态 telegraph 切换（#12）：弱网（高 RTT）强制静态，与不等式目标一致——既是可访问性也是 P3 保底。

## 4. 开放问题与状态
1. **【已决（用户批准）】** telegraph 的 DANGER 红区**豁免** art-bible §3「强提醒色总面积 < 8%」**全局**纪律：改为"telegraph 自身亮度预算 + 同屏数量预算"约束，由 art-bible §3 修订落地（design-strategist 处理）。本档美术侧据此执行：DANGER 仅限 telegraph 形状内，外环境保持冷色。
2. **【已协同 engineering-lead · 进行中】** HUD 可访问性依赖 ⑬ 接口：ping/延迟/重连指示数据 + 战争迷雾并集多边形（systems-index §5 ⑬）。色盲安全 ping 指示器三重构（图标+文字，不靠色）已与 engineering-lead 对齐，等待工程实现。
3. **【已决】** MVP 交付档 = **Standard**；Comprehensive 留作后续里程碑，不在 MVP 范围。
