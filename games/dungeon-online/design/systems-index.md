## 1. 系统枚举

### 1.1 MVP 主干系统（13 个）
每个一句话定位 + 核心职责。

**1. 联机与房间系统** `[MVP][基座][P4]`
定位：全游戏多人基座，权威服务器架构的入口。负责好友房创建、房间码/链接邀请、2–4 人加入/离开、房间生命周期（集结→下行→Boss/出口→结算）与权威状态持有；P4「断线即重连」由服务器持真相源实现。核心职责：会话/房间生命周期管理、玩家加入握手、权威状态容器（所有实体状态以服务器为真相）、断线检测与状态保留、重连会话恢复。工程接口需求见 §5。

**2. 角色与职业系统** `[MVP][基座][P1]`
定位：玩家与可战斗实体共用的数据 schema 基座。定义 4 职业（守卫士/游侠/术士/医者，覆盖 坦/输出/辅助/控场）的属性（移速/血量/基础攻击）、统一状态容器（HP、status effect、倒地标志、阵营色、职业图标）。每职业 1 主动 + 1 协作技由本系统定义**接口**，具体效果在战斗/协作技系统实现。核心职责：提供玩家与敌人共用的「状态/属性模型」，为战斗、救援、技能、敌人提供统一数据底座，避免各系统自造状态造成不一致。

**3. 敌人与资源数据定义** `[MVP][基座]`
定位：纯数据层，把「有哪些敌人/资源及其参数」与「如何生成」解耦。定义敌人原型表（杂兵/精英/Boss 属性、剪影、攻击 telegraph 参数）与资源原型表（药品/弹药/增益类型与效果）。核心职责：供地牢生成按类型 ID 放置、供战斗/敌人运行时引用；是打破「地牢↔敌人」循环依赖的关键（见 §2.3）。

**4. 输入与客户端预测系统** `[MVP][P3]`
定位：玩家操作到网络的桥梁。采集本地输入、做客户端预测保手感、上报服务器、接收权威状态并回正（reconciliation）+ 插值。核心职责：输入采样与上报、本地预测表现、服务器状态回正、延迟期表现平滑；直接决定 P3 在 Web 延迟下的体验下限。需 程基岩 ADR（tick rate / RTT 预算 / 预测回正策略）见 §5。

**5. 地牢生成系统** `[MVP][P2]`
定位：单局世界构造。覆盖 1 生物群系（余烬矿坑），固定模板 + 轻量随机（房间顺序、敌人点位、资源点、层间分支）。产出可遍历房间图、刷怪点、资源点、层下行结构，并承载「商(Regroup)」所需的层间休息点标记。核心职责：基于种子**确定性**生成（供重连恢复），产出供探/战/拾/下 落位的数据；只依赖敌人/资源数据定义（类型 ID），不依赖敌人运行时（见 §2.3）。

**6. 资源与掉落系统** `[MVP]`
定位：局内有限资源的放置与分配。药品/弹药/增益在地图节点**固定放置**（非程序化掉落表），拾取后进入队伍/个人库存，由玩家实时谈判分配。核心职责：资源节点放置（依赖地牢生成）、拾取判定、库存与分配（依赖角色状态）、结算清点。MVP 不做局外经济/交易，防过度设计（范围蔓延风险见 §2.4）。

**7. 战斗系统** `[MVP][P3]`
定位：全实体（玩家**与**敌人）的伤害与状态结算权威。处理移动/普攻/闪避（i-frame）/技能命中、伤害计算、状态效果（眩晕/减速/增益）、命中判定——全部由服务器逐 tick 裁定，客户端仅预测表现。核心职责：统一伤害/状态结算核心（玩家与敌人共用）、闪避无敌帧、技能生效；为敌人/AI、协作技、救援提供结算入口。可读预警的形状/色块由本系统与敌人 telegraph 共同保证（P3 硬约束）。

**8. 敌人与 AI 系统** `[MVP][P3]`
定位：敌人的行为、刷新与攻击表达。基于地牢刷怪点生成杂兵/精英/Boss，驱动行为（寻路/攻击选择/编队）；所有攻击以**静态可读 telegraph**（≥0.6s 前摇 + 形状 + 色块 + 声）呈现，Boss 分阶段。核心职责：刷怪（依赖地牢生成刷怪点）、AI 行为、攻击 telegraph 生成、伤害**请求**（交由战斗系统裁定，不自行结算）。攻击前摇下限与 tick 率耦合，须 程基岩 定（P3，见 §5）。

**9. 协作技系统** `[MVP][P1]`
定位：P1「协同至上」的核心载体。每职业 1 协作技，需队友协同触发（如坦的护盾墙需队友进入范围 / 医者的救援链需锁定倒地友军 / 控场的合围需两人同侧），强调「配合才生效、配合更强」。核心职责：协作技触发条件/连携判定（依赖战斗 + 角色状态 + 联机同步）、协同增益结算（入战斗系统）。是协同支柱的最小可玩验证点。

**10. 救援与倒地系统** `[MVP][P1][P4]`
定位：死亡非终局 + 无缝重连的交汇点。HP 归 0 进入「倒地」而非死亡，队友靠近读条救援归队；倒地状态由服务器持有，掉线玩家角色冻结/托管不终止循环。核心职责：倒地检测（依赖战斗 HP）、救援读条（依赖信号呼救 + 角色状态）、服务器托管快照（依赖联机/房间，供重连归位）。同时服务 P1（救不救的戏剧抉择）与 P4。

**11. 信号与沟通系统** `[MVP][P1]`
定位：无语音也能协作的快捷沟通。ping/标记/表情/急救呼救，世界内与 HUD 内呈现。核心职责：信号输入（依赖输入系统）+ 广播（依赖联机）+ 事件流输出（供 HUD 渲染、供救援呼救）。是「商(Regroup)」实时谈判的沟通载体。

**12. 进度与结算系统** `[MVP]`
定位：单局进程的推进与收口。追踪层下行（探→下）、触发 Boss、判定通关/团灭、结算得失与局内 Build 选择结果。核心职责：楼层推进（依赖地牢生成）、Boss 触发（依赖战斗胜负面）、结算（依赖战斗 + 资源清点 + 联机房间生命周期）。把核心循环在「出口/Boss→结算」闭合。

**13. HUD 与 UX 系统** `[MVP][P3]`
定位：所有信息的可读呈现。队伍面板（4 头像+血条+状态，阵营色）、技能/快捷栏、连接/延迟指示（权威服务器必显 ping/重连）、倒地/救援环形进度、地图 ping、Boss 血条。核心职责：聚合各系统状态做极简贴边呈现，遵守色盲安全 + 不遮挡玩法区（art-bible §8/§10）。延迟指示与迷雾并集数据来自工程层（见 §5）。

> 说明：MVP 的「局内 Build 决策纵深」（职业/路线/资源分配的选择）是**跨系统选择空间**，由 角色/职业 + 地牢生成(分支) + 资源分配 共同承载，**不单独立系统、不写八节**；正式 Build 系统（装备/perk）归 §1.2 延展。

### 1.2 延展系统（已移出 MVP，仅规划）
- **随机/快速匹配系统** `[延展]`：陌生人组队，依赖好友房成熟后迭代。
- **程序化地牢生成系统** `[延展]`：提升 P2 重玩；MVP 为固定模板+轻量随机，勿提前膨胀。
- **多生物群系系统** `[延展]`：2–3 额外群系 + 主题敌人/Boss。
- **装备/perk Build 系统** `[延展]`：局内装备/perk 槽 + 掉落，落 P2 反主导策略评审。
- **物品经济系统** `[延展]`：局内掉落 + 局外存档，非交易市场。
- **Meta 持久成长系统** `[延展]`：跨局解锁/构筑。
- **动态难度系统** `[延展]`：服务器按小队表现微调密度；MVP 不做，防过度设计。
- **排行榜系统** `[延展]`：非 PvP。
- **内嵌语音系统** `[延展]`：更丰富沟通（信号系统之外的增强）。
- **好友系统增强** `[延展]`：邀请增强（如平台好友导入）。

## 2. 依赖排序

### 2.1 分层 DAG（Layer 0–3，自上而下无环）
- **Layer 0 · 基座（无依赖）**：① 联机与房间 ｜ ② 角色与职业 ｜ ③ 敌人与资源数据定义
- **Layer 1 · 世界与输入（依赖 L0）**：④ 输入与客户端预测 → ① ｜ ⑤ 地牢生成 → ③ ｜ ⑥ 资源与掉落 → ② + ⑤
- **Layer 2 · 运行时玩法（依赖 L0–L1）**：⑦ 战斗 → ② + ④ + ① ｜ ⑧ 敌人与 AI → ⑤ + ⑦ + ② ｜ ⑨ 协作技 → ⑦ + ② + ① ｜ ⑩ 信号与沟通 → ① + ④ ｜ ⑪ 救援与倒地 → ⑦ + ② + ① + ⑩
- **Layer 3 · 循环闭合并呈现（依赖 L0–L2）**：⑫ 进度与结算 → ⑤ + ⑦ + ① + ⑥ ｜ ⑬ HUD 与 UX → ① + ② + ⑦ + ⑧ + ⑪ + ⑥ + ⑩

### 2.3 循环依赖纪律（两处关键单向化）
- **风险点 A · 地牢生成 ↔ 敌人与资源**：纪律——地牢生成（L1）**只**依赖 L0「敌人与资源数据定义」（引用类型 ID），**绝不**依赖敌人运行时（L2）；敌人运行时（L2）反向依赖地牢生成的刷怪点（L1）。单向，破环。
- **风险点 B · 战斗 ↔ 敌人与 AI**：纪律——战斗系统（L2）是「通用伤害/状态结算权威」，**不**依赖敌人运行时；敌人与 AI（L2）仅决策行为并发出「伤害请求」交由战斗裁定。二者共用底座为 ② 角色与职业的状态模型（L0）。单向，破环。

### 2.4 范围蔓延纪律（Lean 红线）
- 地牢生成严守「固定模板 + 轻量随机」，不滑向程序化生成（那是延展，且是 P2 重玩验证后的决策）。
- 资源与掉落严守「固定放置 + 实时分配」，不滑向局内经济/交易（经济失衡红线）。
- 「商(Regroup)」用 信号 + 资源分配 + HUD + 地牢休息点标记 承载，**不**立独立安全屋系统；避免为单一循环节点制造新系统。

## 3. 核心循环贯通校验（探→战→拾→商→下→Boss→结算）
| 循环动词 | 承担系统 | 缺口？ |
|---|---|---|
| 探 Explore | ⑤地牢生成 + ⑧敌人(刷新) + ①联机(迷雾并集) | 无 |
| 战 Fight | ⑦战斗 + ⑨协作技 + ⑧敌人 + ⑪救援 + ④输入预测 | 无 |
| 拾 Loot | ⑥资源与掉落 + (Build 决策空间) | 无 |
| 商 Regroup | ⑩信号 + ⑥资源分配 + ⑬HUD + ⑤地牢(休息点) | 无 |
| 下 Descend | ⑫进度与结算 + ⑤地牢生成(新层) | 无 |
| Boss | ⑧敌人(Boss阶段) + ⑦战斗 + ⑨协作技 | 无 |
| 结算 Settle | ⑫进度与结算 + ⑥清点 + ①房间生命周期 | 无 |

结论：MVP 主干 13 系统使核心循环在「断线成员动态进出」前提下仍闭环，无缺口。

## 4. 推荐优先写 GDD 的核心系统（6 个，承载支柱且决定架构/netcode 走向）
1. **① 联机与房间系统** — 架构基座，P4 前提，一切同步的根源；必须先定，否则其余系统无法定网络语义。
2. **④ 输入与客户端预测系统** — netcode 关键路径，决定 P3 延迟下限；须与程基岩 ADR（tick/RTT/回正）同步定稿。
3. **⑦ 战斗系统** — 核心玩法手感与伤害权威，承载 P3 可读预警；向上支撑敌人/协作技/救援。
4. **⑤ 地牢生成系统** — 闭合 探/下 循环，P2 每局新谜题的来源；决定单局结构与重连恢复的种子策略。
5. **⑧ 敌人与 AI 系统** — P3 可读 telegraph 的落地处，Boss 体验来源，闭合 战 循环。
6. **⑪ 救援与倒地系统** — P1（救不救的抉择）与 P4（服务器托管重连）的交汇，强耦合战斗+联机，宜早定以固化协同与重连边界。

> 紧随其后的次优先：⑨ 协作技（P1 最小验证点，坐于战斗之上）、⑬ HUD/UX（所有信息汇聚，建议在中后段定以避免返工）。

## 5. 需 engineering-lead（程基岩）承接的工程接口（仅标注接口需求，不代写方案）
- **① 联机与房间**：需定 transport、会话/房间服务、权威状态容器、重连会话恢复。接口需求——房间生命周期事件协议、状态快照格式、重连握手流程。
- **④ 输入与客户端预测**：需 ADR。接口需求——tick rate、RTT 容忍上限、输入采样率、输入指令 schema、服务器→客户端状态 diff 格式、回正/插值策略边界。
- **⑦ 战斗**：接口需求——逐 tick 伤害/状态结算时序、命中/碰撞权威判定点、与客户端预测的回正对齐方式。
- **⑧ 敌人与 AI**：接口需求——攻击 telegraph 前摇下限常量（P3 ≥0.6s，按 tick 率定），telegraph 形状/色块/声的同步时序。
- **⑪ 救援与倒地**：接口需求——掉线托管期间状态快照频率、重连归位（state snap 归位）边界，避免重连瞬间状态跳变。
- **⑬ HUD 与 UX**：接口需求——从 netcode 暴露的 ping/延迟/重连指示数据；**战争迷雾取各玩家视野并集（union）**的逐玩家可见多边形输出（engine：Light2D/可见性多边形，art-bible §5【待引擎】）。
- **⑤ 地牢生成**：接口需求——确定性种子 + 布局快照，供服务器持有并重连恢复（与 ① 重连恢复对接）。
- **⑫ 进度与结算**：接口需求——权威 run 状态供结算与重连（与 ① 房间生命周期对接）。

## 6. 跨职能约束（来自 art-bible，设计须遵守，不可在 GDD 中违反）
- **P3 可读性硬约束**：所有危险（敌人攻击前摇/陷阱/AOE）须静态可读形状 + 色块预警，第一帧可读，不靠细微动效；前摇 ≥0.6s（下限随 tick 率由程基岩定）。战斗/敌人/地牢/HUD 均须对齐。
- **色盲安全**：核心语义形状+图标+文字三重编码，不依赖颜色 alone（art-bible §10）。HUD/敌人 telegraph 须遵守。
- **阵营色纪律**：玩家色仅用于角色描边/名牌/自身技光效；GOLD/EMBER/DANGER 为强提醒色，总面积 < 8%（避免霓虹过载）。
- **可访问性底线（Lean 不可砍）**：安全调色板 + 达标对比度 + 按键重映射 + 颜色不单独编码 + 危险静态预警。
- **战争迷雾并集**：联机取玩家视野并集，属 engine 接口（见 §5），地牢探索与 HUD 设计须预留并集表现。
