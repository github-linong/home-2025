## §2 设计理论评审

### 2.1 四设计支柱对齐（无支柱漂移）

| 支柱 | 承载系统 | 评审结论 |
|------|---------|---------|
| **P1 协同至上** | ⑨协作技（待 Phase 3）/ ⑪救援 / ①联机 | 胜利路径强制协同：倒地须队友救援（⑪），单人无法靠纯数值通关 MVP 小队内容；无"单机碾压"主导策略 → 支柱稳固 |
| **P2 每局新谜题** | ⑤地牢生成 / ③数据 | ⑤ 仅引用 ③ 数据 ID + seed 化生成，保证每局布局/遭遇不同；与 P1 协同解谜（机关+救援）叠加 → 支柱稳固 |
| **P3 读得懂的紧张感** | ⑦战斗 / ⑧敌人AI / ④输入 / art-bible | telegraph 静态可读 + 色盲三重编码 + P3 不等式保底（C2）；弱网下可读紧张感不崩塌 → 支柱稳固 |
| **P4 断线即重连** | ①联机 / ⑪救援 / ⑦战斗 | 托管暂停计时 + 重连还原原状态（C4）；公共体验房 RESIDENT 常驻 → 掉线不破坏关系与进度 → 支柱稳固 |

### 2.2 SDT 自我决定论映射

- **自主（Autonomy）**：职业选择 + 每局随机地牢（P2）+ 协作技组合空间 → 玩家有策略选择权。
- **胜任（Competence）**：P3 可读预警让玩家"学得会应对"，难度可学习、可 mastery；无隐藏即死机制。
- **关系（Relatedness）**：P1 协同 + P4 断线即重连 → 社交联结不被网络故障破坏；公共体验房强化轻社交。

### 2.3 Bartle 玩家类型覆盖

- **成就型（Achiever）**：进度/通关/Boss（⑫待 Phase 3）。
- **探索型（Explorer）**：每局新谜题（P2 / ⑤）。
- **社交型（Socializer）**：协同玩法（P1）+ 公共体验房。
- **杀手型（Killer）**：战斗对抗、救援博弈（⑦/⑪）。

### 2.4 设计理论红线检查

- **主导策略（Dominant Strategy）**：未发现。协同为唯一胜利路径，纯数值/单人无法绕过（P1 硬约束）。
- **经济失衡（Economic Imbalance）**：MVP 资源循环轻量，战斗与经济解耦（⑥ 负责，延展）；无通胀/稀缺崩溃信号。
- **认知过载（Cognitive Overload）**：telegraph 静态可读 + 色盲三重编码 + 阵营色纪律（提醒色总面积 <8%，art-bible）→ 无过载。
- **支柱漂移（Pillar Drift）**：四支柱均无漂移（见 2.1）。

**结论**：设计理论评审 PASS，SDT / Bartle 映射一致，四条红线均未触发。
