# GDD ⑦ 战斗系统（Combat）
**路径**：`games/dungeon-online/design/gdd/07-combat.md` ｜ 标记：`[MVP][P3]`
**依赖（systems-index §2）**：依赖 ②角色与职业 + ④输入/预测 + ①联机与房间（L2→L0/L1）；被依赖 ⑧⑨⑪⑫⑬。
**循环依赖纪律 B（systems-index §2.3）**：战斗是「通用伤害/状态结算权威」，**不依赖敌人运行时**；敌人与 AI 仅决策行为并发出「伤害请求」交由战斗裁定。本 GDD 代码/文档边界须标注此纪律。

## 1. 目的与支柱对齐
解决全实体（玩家**与**敌人）伤害与状态结算的单一权威，定义战斗手感与"读得懂的紧张感"。服务 **P3**（可读预警的形状/色块，与 ⑧ telegraph 共同保证），向上支撑 ⑧敌人/AI、⑨协作技、⑪救援。不引入经济/掉落（资源系统 ⑥ 负责），不引入 perk/Build（延展）。

## 2. 依赖与上游接口
- **依赖**：② 角色与职业（状态/属性模型：HP/status/hitbox 引用）、④ 输入/预测（输入指令）、① 联机/房间（权威状态容器 + diff 下发）。
- **提供接口（被依赖方）**：
  - → ⑧ 敌人/AI：伤害/状态**结算入口**（敌人攻击 → 战斗裁定，不自行结算）。
  - → ⑨ 协作技：协同增益/效果结算入口（协作技效果经战斗施加）。
  - → ⑪ 救援：HP 归零检测 → 触发倒地（救援系统接管）。
  - → ⑫ 进度：战斗胜负（Boss HP=0 / 团灭）事件。
  - → ⑬ HUD：HP/状态/CD 数据。
- **上游接口需求（→程基岩）**：逐 tick 结算时序、命中/碰撞权威判定点、与预测回正对齐（systems-index §5 ⑦）。

## 3. 核心机制
- **统一结算核心**：所有伤害/状态效果由战斗在服务器逐 tick 裁定，玩家与敌人共用同一套（基于 ② 状态模型）。
- **移动**：位置由输入指令驱动（预测+服务器权威），碰撞/边界由地牢几何约束（只读地牢碰撞层）。
- **普攻**：近战/远程命中判定（hitbox/射线），服务器 tick 内结算，CD 约束。
- **闪避**：触发后获 i-frame（无敌帧），期间免疫伤害；有 CD。
- **技能**：各职业 1 主动技，效果经战斗结算（伤害/位移/增益）；协作技经 ⑨ 触发后也入战斗结算。
- **状态效果**：眩晕（禁用输入/AI）、减速（移速乘子）、增益（攻/防/速 buff）、DoT 等，统一由战斗维护 duration 与结算。
- **伤害请求协议**：任何来源（玩家技能/敌人攻击/陷阱/协作技）提交 `伤害请求(source, target, amount, type, application_tick)` → 战斗校验合法性（i-frame? 存活? 范围命中?）→ 应用 → 写权威状态。
- **倒地触发**：HP≤0 → 战斗置"倒地"标志（不死，交 ⑪ 救援），不销毁。

## 4. 数值/平衡初稿（`待调`）
- **`TICK_RATE`：引用 `ADR-NET-01`（锁 30Hz），本系统不再单独定义。**
- 基础 HP（②定义，战斗引用）：坦 **140** / 输出 **80** / 辅助 **90** / 控场 **100**。
- 移速(px/s，32px tile)：坦 140 / 输出 185 / 辅助 165 / 控场 170。
- 普攻：CD **0.4s**（CLASS_BASE.attackCooldownMs=400；world 暂未强制 CD 闸门，P5 评估，见 E5 O-L），伤害 **18（全职业统一，服务端 `resolveDamage` 裁决、忽略客户端 amount；职业差异在 ②/⑨/E8 落地）**。
- 闪避：i-frame **0.4s（12 tick @30Hz，`DODGE_IFRAME_TICKS=12`）**；**无独立冷却闸门**（DODGE 直接授予 iframe 窗口，过期后可再闪避；0.8s CD 为设计意图，P5 评估是否落地）。
- 技能 CD：**6–10s**（各职业不同）。
- 状态：眩晕 1.0s；减速 移速×0.5/2s；增益 +20% 攻/3s。
- 伤害类型：MVP **仅物理**（元素留延展，防过度设计）。

## 5. 状态机/流程
- **实体状态位（types.EntityStatus，代码权威，每 tick 紧凑序列化）**：`ALIVE=1<<0`、`DOWNED=1<<1`、`OUT=1<<2`、`DEAD=1<<3`、`IFRAME=1<<4`、`STUN=1<<5`、`SLOW=1<<6`、`BUFF=1<<7`；位运算组合。`DOWNED` 与 `OUT` 互斥（超时清 DOWNED 置 OUT）；`IFRAME` 由 DODGE 授予、过期清除（E5 O-M 修复）；`OUT` 仅超时触发，绝不经由伤害结算（S7.4）。
- 玩家：`ALIVE` → 受击(HP↓) → HP≤0 → `DOWNED`(倒地, 交 ⑪) → 救援成功回 `ALIVE` / 超时→(由 ⑪ 定：托管/观战/本局出局)。
- 敌人：`SPAWN` → `ACTIVE`(行为+telegraph) → 受击(HP↓) → `DEAD`(移除) / BOSS 分阶段。
- **战斗结算 tick 流程**：收集本 tick 全部伤害请求 → 校验(i-frame/存活/命中) → 应用 → 写权威状态 → 触发倒地/Boss 阶段事件 → 联网下发 diff。

## 6. 联机/权威服务器影响
- 全部伤害/状态/命中在服务器逐 tick 裁定（P3 公平，避免"赢了被延迟坑"）。
- 客户端仅预测表现；战斗结算结果作为权威 diff 经 ① 下发，④ 据其回正。
- **与 ④ 回正对齐边界**：战斗不保证"客户端预测即正确"——击退/打断/伤害以服务器为准，④ 负责平滑回正（契约见 ④ §8 / 本 §8）。
- 断线：掉线玩家角色由 ① 保留状态、⑪ 冻结/托管，战斗对其跳过 tick 应用（不结算其输入），重连后归位继续。

## 7. 可读性/UX 约束（P3 硬约束，与 ⑧ telegraph 协作）
- 所有战斗危险（敌人攻击前摇/陷阱/AOE/自身技能范围）须**静态可读形状 + 色块预警**，第一帧可读，不靠细微动效（art-bible §7）。
- **【跨 GDD 一致性约束 · P3 保底 · 已锁 ADR-NET-01（D3）】预警前摇与 RTT 容忍不等式**：telegraph **预警前摇 ≥ max(P3 硬下限 0.6s, RTT 容忍上限 250ms + 表现余量 K 100ms)**。已锁 `ADR-NET-01`（D3）：RTT 上限 250ms + K 100ms = 350ms < 0.6s（600ms），**硬下限 0.6s 主导**；telegraph 下限 = 18 tick（@30Hz）。与 ④ §7 / ⑧ §4、§7 同文。该不等式是 P3「读得懂的紧张感」在弱网下的保底条件——预警须早于"网络延迟 + 表现余量"即可被玩家读取并反应，否则弱网下可读紧张感崩塌。
- **与 ⑧ 的时序对齐（保留）**：⑧ 生成 telegraph，战斗在其"应用 tick"结算伤害——时序：预警出现 → 前摇计时 → 达应用 tick → 战斗结算伤害。前摇时长须满足上式不等式。
- 色盲三重编码：危险=DANGER 色 + 形状(圆环/AOE 填充) + 图标/文字，不靠色 alone。
- 阵营色纪律：玩家技光效用各自阵营色；GOLD/EMBER/DANGER 为提醒色，总面积 <8%（避免霓虹过载）。
- 闪避 i-frame 表现：清晰静态视觉（描边变亮/护盾形状），不靠细微动效暗示无敌。

## 8. 开放问题与工程接口
- 引用 systems-index §5 ⑦：逐 tick 结算时序、命中/碰撞权威判定点、与预测回正对齐（统一为 `ADR-NET-01`）。
- **设计层需求（→程基岩 `ADR-NET-01`）**：
  1. 逐 tick 结算时序约定（伤害请求 收集→校验→应用→下发 的顺序与时机，**下发使用 ① 定义的 diff 格式**）。
  2. 命中/碰撞权威判定点（服务器何 tick 判定 hitbox 命中；客户端预测用何近似）。
  3. 与 ④ 预测回正对齐契约：本系统作为 **producer** 产生战斗结算结果 diff，经 ①（format-owner）定义格式下发，④（consumer）消费回正（角色见 ① §8）。
  4. `TICK_RATE`：引用 ① 契约（不单独定义）。
- **纪律 B 落地**：本系统禁止 import 敌人运行时；敌人仅通过"伤害请求"协议交互（GDD 与代码边界标注）。
- **开放问题**：已定：MVP 仅物理，元素留延展（见 §4）。倒地超时后该玩家状态由 ⑪ 定，本系统仅提供 HP≤0 事件。
