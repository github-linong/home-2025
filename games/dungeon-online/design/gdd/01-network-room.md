# &#x20;GDD ① 联机与房间系统（Network & Room）

**路径**：`games/dungeon-online/design/gdd/01-network-room.md` ｜ 标记：`[MVP][基座][P4]`  
**依赖（systems-index §2）**：依赖无（L0 基座）；被依赖 ④⑦⑧⑨⑪⑫⑬。

## 1. 目的与支柱对齐（修订后）

解决多人会话的建立、权威状态持有与断线重连；是 P4「断线即重连」的前提，也是其余所有系统网络同步的基座。提供两种房间类型：**好友房**（房间码/链接邀请，2–4 人，MVP 主路径）与**公共体验房**（服务器常驻、无码、任意加入，Web 端即开即玩入口）；二者均走权威服务器、均遵守断线托管/重连（P4）。间接服务 P1（稳定联机才能协同）与 P3（HUD 延迟可见性依赖联网状态）。设计红线：自身不引入经济/匹配逻辑（随机匹配属延展），不越界定义玩法。

## 2. 依赖与上游接口

- **依赖**：无（仅依赖外部 transport，归程基岩，见 §8）。
- **提供接口（被依赖方）**：
  - → ④ 输入/预测：权威状态容器读取 + 状态 diff 下发端点 + 输入接收端点。
  - → ⑦ 战斗：实体权威状态容器（战斗逐 tick 写入，联网负责广播 diff）。
  - → ⑧⑨⑩⑪⑫⑬：房间生命周期事件（加入/离开/阶段变更）、权威状态读取、断线/重连事件通知。
- **上游接口需求（→程基岩）**：transport、会话/房间服务、权威状态容器、重连恢复（systems-index §5 ①）。

## 3. 核心机制（修订后）

- **房间类型**：
  - **好友房**：任一客户端发"创建房间"→ 服务器分配 `room_id` + 6 位房间码 + 邀请链接（含一次性 token）。房间码/链接分享即可加入；2–4 人；满员拒绝。
  - **公共体验房（常驻 demo 房）**：服务器进程级常驻、无房间码、任意玩家经 Web 端（lilnong.top）入口即可加入；非随机匹配、非好友房，是"即开即玩"体验入口。与好友房并行不冲突（好友房为主、公共房为常驻体验）。公共房生命周期为服务器进程级常驻，不进入 `CLOSED` 直至服务下线；仍遵守断线托管/重连（P4）与权威状态持有。
- **好友房创建/加入**：房间码校验 + 链接 token 校验防滥用。
- **离开/踢出**：主动离开或房主/co-host 踢出；最后一人离开→房间销毁（公共房除外，常驻不销毁）。
- **房主与管理权（co-host）**：权威服务器下无网络 host 概念，**房主 = 房间管理员**（仅好友房有）；设立**联席主持人(co-host)** 角色（可多人持有）。房主掉线后管理权**自动迁移**给下一位 co-host（无 co-host 则按加入顺序顺位队员），房间不因管理员掉线关闭（契合 P4）。co-host 生成规则：创建时房主默认为 admin；按**加入顺序**自动指定前序队员为 co-host（预留投票改选接口，属延展）。co-host 权限：踢人 / 开局 / 改设置（与房主同权，admin 为 co-host 之一）。
- **权威状态容器**：服务器持有单一权威世界状态（所有实体 transform / HP / status / 房间阶段）。客户端只持预测副本 + 接收 diff。客户端不为真相源。
- **断线检测**：服务器心跳超时判定断线；不立即销毁角色，进入"托管/冻结"状态（角色状态保留，具体托管策略由 ⑦/⑪ 定义，联网负责保留 slot 与状态）。
- **重连**：同一玩家凭 `room_id` + 身份 token 重连 → 服务器从权威快照恢复其角色状态归位（公共房同此流程）。

## 4. 数值/平衡初稿（修订后）

- 房间码：6 位 base32（排除易混字符 I/O/0/1），时效至房间销毁或 24h。
- 最大人数：**4**；**最小开局人数：1（允许 solo 完整通关，不仅是调试）**。
- 断线心跳超时：**5s** 无心跳判定断线（绝对阈值，与 RTT 解耦，避免高延迟误判；`待程基岩按网络层定`）。
- 重连窗口：无硬性上限（只要房间未结算/服务未下线），状态保留至房间结束。
- co-host 人数：默认按加入顺序自动授予（可多人），上限 `待调`（建议 ≤2，防权限分散）。
- **`TICK_RATE`（全局唯一初值注记，待调）**：**30 Hz**（33.3ms/tick）。此为本数值在三份 GDD 中的**唯一初值落点**；netcode state-diff 契约的定值、下发节奏与状态 diff schema 由程基岩 P3 ADR（`ADR-NET-01`）锁定，④/⑦ 仅引用、不各自定义（角色见 §8）。

## 5. 状态机/流程（修订后）

房间生命周期（好友房）：  
`EMPTY` → `LOBBY`(集结：加入/选职业/准备) → 全员准备或房主开 → `ACTIVE`(下行：探→战→拾→商→下 循环) → 触发 Boss → `BOSS` → 通关或团灭 → `SETTLE`(结算) → 回 `LOBBY`(再来) 或 `CLOSED`(销毁)。

- **开局人数**：房间支持 **1–4 人**，**1 人即开局**（solo 完整进行一局，走完整核心循环）。
- **协同类机制降级（<2 人）**：商(Regroup) 退化为自处理（单人无谈判对象）；救援 退化为倒地后**自救读条**（详见 ⑨ 协作技 / ⑪ 救援与倒地 的 solo 降级分支）。≥2 人时走完整协同。
- **断线分支**：`ACTIVE/BOSS` 中玩家 → `DISCONNECTED`(角色托管，房间继续) → `RECONNECTED`(归位，回 `ACTIVE/BOSS`)。
- **管理权迁移分支**：房主 `DISCONNECTED` → 管理权自动迁移至 co-host / 下一顺位队员 → 房间继续（不进入 `CLOSED`，契合 P4）。
- 全员离开/团灭且无重连 → `SETTLE` / `CLOSED`（**公共体验房除外**：常驻不销毁，仅服务下线才终止）。
- **公共体验房生命周期**：服务器进程级常驻（`RESIDENT`），不经历 `LOBBY`/`CLOSED` 常态流转；玩家加入/离开仅为"在场集合"变更，房间本身常驻至服务下线。

## 6. 联机/权威服务器影响

- 所有房间阶段、加入/离开、实体权威状态、断线判定**均由服务器裁定**。
- 客户端不持真相：输入→服务器→算完→下发 diff。
- 断线：服务器保留该玩家 slot 与权威状态（冻结），小队继续；重连即从快照归位，一局不散（P4 落点）。
- 重连归位防跳变：详见 ⑦/⑪ + 程基岩（快照频率、归位插值）。

## 7. 可读性/UX 约束

- HUD 必显连接/延迟：ping、重连状态（橙/绿信号，**图标+文字三重**，不靠色 alone）。
- 阵营色纪律：联网分配 4 阵营色（P1 蔚蓝/P2 紫罗兰/P3 品红/P4 春绿，art-bible §3），仅用于角色描边/名牌。
- 战争迷雾并集：联网须向引擎/HUD 提供各玩家可见多边形**并集**输出（art-bible §5，引擎接口见 ④/⑬/程基岩）。

## 8. 开放问题与工程接口（修订后）

- 引用 systems-index §5 ①：transport / 会话服务 / 权威状态容器 / 重连恢复**归程基岩**。
- **Netcode State-Diff 契约（单一真相源，归程基岩 P3 ADR `ADR-NET-01`）——角色边界**：
  - **format-owner（定义方）= 本系统 ①**：定义权威状态快照格式与下发协议（实体状态序列化 schema、下发节奏、与 `TICK_RATE` 绑定）。
  - **producer（产生方）= ⑦ 战斗**：产生"战斗结算结果"作为权威 diff（伤害/状态/命中），写入本系统定义的容器，由本系统广播。
  - **consumer（消费方）= ④ 输入/预测**：消费本系统下发的 diff 做回正(reconciliation)与插值，不反向修改格式。
  - `TICK_RATE` 全局唯一初值注记见 §4（30Hz，待调）；`ADR-NET-01` 锁定后三份 GDD 均改为"引用 `ADR-NET-01`"，删除散落初值。
- **设计层需求（交程基岩 `ADR-NET-01`）**：
  1. 房间生命周期事件协议（LOBBY/ACTIVE/BOSS/SETTLE 状态变更事件定义；公共体验房 `RESIDENT` 常驻态另定）。
  2. 权威状态快照格式（实体状态序列化 schema，供战斗/输入读写）——即本契约 format-owner 职责。
  3. 重连握手流程（身份 token 校验 + 快照拉取 + 归位）。
  4. 断线心跳/超时阈值（设计建议 5s，待程基岩按网络层定）。
  5. `TICK_RATE` 定值与 netcode state-diff 下发节奏（设计建议 30Hz，待锁定）。
- **已拍板决策落点（用户，经主理人转交）**：
  - 最小开局人数 = 1（solo 完整通关）：见 §4 / §5。
  - 房主掉线管理权自动迁移 + 联席主持人(co-host)：见 §3 / §5（已移除"host 迁移待拍板"标记）。
  - 公共体验房（常驻、无码、任意加入）：见 §1 / §3 / §5。
  - **【P4 保底契约 · ⑪↔①/⑦】**：掉线托管期间，⑪ 的 `DOWNED` 状态与救援读条**计时暂停**；重连还原至掉线瞬间原状态（`DOWNED`/`ALIVE`，含剩余窗口），**不误判超时→OUT**。由本系统托管快照 + ⑦ 断线跳过 tick 协同实现；频率/归位边界由 `ADR-NET-01` 落地。与 ⑪ §6/§8 同文。
- **剩余开放问题**：co-host 人数上限（建议 ≤2）与投票改选是否 MVP 引入？`待调`。
