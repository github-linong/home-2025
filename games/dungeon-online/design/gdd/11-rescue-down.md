# GDD ⑪ 救援与倒地系统（Rescue & Down）
**路径**：`games/dungeon-online/design/gdd/11-rescue-down.md` ｜ 标记：`[MVP][P1][P4]`
**依赖（systems-index §2）**：依赖 ⑦ 战斗(HP=0→DOWNED) + ② 角色状态 + ① 联机/房间(托管重连) + ⑩ 信号(呼救)；被依赖 ⑬。

## 1. 目的与支柱对齐
解决"死亡非终局"与无缝重连的交汇点。**P1（救不救的戏剧抉择）** + **P4（服务器托管重连）** 双支柱服务。HP=0 → `DOWNED`（不死），队友救援归队；倒地状态由服务器持有，掉线不终止循环。

## 2. 依赖与上游接口
- **依赖**：⑦ 战斗（HP≤0 → `DOWNED` 事件，L2）、② 角色状态（`DOWNED` 标志/状态，L0）、① 联机/房间（托管/重连，L0）、⑩ 信号（呼救广播，L2）。
- **提供接口（被依赖方）**：→ ⑬ HUD：倒地/救援环形进度 + 状态。
- **上游接口需求（→程基岩）**：托管快照频率、重连归位边界（systems-index §5 ⑪）。

## 3. 核心机制（含用户拍板决策）
- **倒地触发**：⑦ 检测 HP≤0 → 战斗置 `DOWNED` 标志（不死、不销毁），本系统接管。
- **自救/救援**：≥2 人时，队友靠近读条救援归队；**solo（<2 人）时自救读条**（引用 ① §5 solo 降级分支）。
- **呼救**：`DOWNED` 时经 ⑩ 信号广播急救呼救（世界内 + HUD 图标）。
- **救援读条**：静态环形进度 + 图标（不靠变色，对齐 art-bible §8/§10）。
- **DOWNED 期间免疫补刀致死（用户拍板）**：`DOWNED` 状态下玩家**免疫进一步致死伤害**（MVP 不做补刀致死），保 P4 友好、降低劝退；敌人可持续攻击但仅维持 `DOWNED` 计时，不致死。
- **超时处理（用户拍板）**：`DOWNED` 超时未救援 → 该玩家进入 `OUT`（本局观战，下局再战；MVP 不做永久死亡，团灭才结算），不影响仍是 ALIVE 的队友继续推进。

## 4. 数值/平衡初稿（`待调`）
- `DOWNED` 窗口（倒地超时）：**20s（`DOWNED_TIMEOUT_TICKS=600` @30Hz）**；命中 e7 契约上界（原 GDD 建议 15–20s，代码钉为 20s）。
- 救援读条时长：**3s（`RESCUE_TICKS=90` @30Hz，靠近读条）**。
- 自救读条时长（solo 降级）：**10s（`SOLO_SELF_RESCUE_TICKS=300` @30Hz，复活为 1hp 降级态）**；原 ux-spec 建议 5s，E7 实现为 10s（O-A7 双源已统一为代码值）。
- `DOWNED` 期间：**免疫进一步致死**（保 P4 友好；用户拍板，MVP 不做补刀致死）。
- 超时结果：`OUT`（本局观战，下局重置 ALIVE；用户拍板）。
- 救援邻近半径：`RESCUE_RADIUS=48`（约 1.5 个 32px tile；欧氏距离平方判定，救援者须在倒地者 48px 内累积读条）。
- 复活回血：队友救援成功 `hp = max(`REVIVAL_HP_MIN=30`, round(maxHp * `REVIVAL_HP_RATIO=0.3`))`；solo 自救复活为 1hp（O-I7：低 maxHp 职业命中 30 下限，P5 评估）。
- 以上阈值全为 **P5 平衡初稿（O-H7）**，待「好玩吗」验证门前端到端复核。

## 5. 状态机/流程
- **实体状态位（types.EntityStatus，代码权威）**：`ALIVE=1<<0`、`DOWNED=1<<1`、`OUT=1<<2`（与 DOWNED 紧邻）、`DEAD=1<<3`；位运算组合。`OUT` 仅由超时触发（清 DOWNED 置 OUT），**绝不**经由伤害结算（S7.4 免疫）；本 run 观战，world reset 才清。
- 玩家：`ALIVE` → (⑦ HP≤0) → `DOWNED` → [≥2人: 队友 rescue 读条成功 → `ALIVE`] / [solo: 自救读条成功 → `ALIVE`] / [超时 → `OUT`(本局观战/下局再战)]。
- **`OUT` 状态语义（用户拍板）**：本局观战、不可被救、下局重置为 `ALIVE`；不影响其他 ALIVE 队友继续推进（团灭才结算）。
- **断线分支**：`DOWNED` 或 `ALIVE` 玩家 `DISCONNECTED` → ① 保留状态 + 本系统冻结/托管 → `RECONNECTED` 归位（对接 ① 重连 + ⑦ 断线跳过 tick）。

## 6. 联机/权威服务器影响（含 P4 保底契约）
- `DOWNED` 状态、救援读条、超时判定均由服务器裁定（权威）。
- 掉线玩家角色由 ① 保留状态、本系统冻结/托管（不终止循环，P4）。
- **【P4 保底契约 · ⑪↔①/⑦】托管期间计时暂停 + 归位还原**：玩家掉线进入托管后，其 `DOWNED` 状态与救援读条**计时暂停**；重连后**还原至掉线瞬间的原状态（含剩余窗口）**，目标状态 = 掉线瞬间的 `DOWNED`/`ALIVE`，**不因托管时长误判超时→`OUT`**（防跳变、保"重连即归队"）。该暂停/还原由 **① 托管快照 + ⑦ 断线跳过 tick** 协同实现。
  - **托管「三者同发」（代码权威，`world.setDisconnected`，D8 端到端测试 1/1）**：断线瞬间① **跳过该玩家 tick**（world.step 排除 `disconnected` 玩家）、② **暂停其 `DOWNED`/救援计时**（`downedTicks`/`rescueTicks` 不动）、③ **单次抓拍 `PersonalState`**（冻结态：status/hp/剩余 `DOWNED` 窗口/救援进度，重连前不被覆盖）。重连（`protocol.session.reconnect` L199 → `validateReconnect` → `world.setDisconnected(false)`）从全量 `WorldSnapshot` 还原 + 续算冻结计时，无跳变。快照频率与归位边界由 程基岩 `ADR-NET-01` 落地。

## 7. 可读性/UX 约束
- 倒地/救援：静态环形进度 + 图标（不靠变色，art-bible §8/§10）。
- 呼救：⑩ 信号图标 + 文字（"急救！"），三重编码。
- 阵营色：倒地玩家描边用自身阵营色 + 弱化（仍辨识），不混淆 DANGER。
- 可访问性：倒地事件有文字提示（不靠音/光 alone，art-bible §10）。

## 8. 开放问题与工程接口
- 引用 systems-index §5 ⑪：掉线托管期间状态快照频率、重连归位边界，避免重连瞬间状态跳变。
- **【P4 保底契约 · ⑪↔①/⑦】**（与 §6 同文，工程落地项）：托管期间 `DOWNED` 与救援读条**计时暂停**；重连还原至掉线瞬间原状态（含剩余窗口），目标 = `DOWNED`/`ALIVE`，**不触发超时判定**。由 ① 托管快照 + ⑦ 断线跳过 tick 协同；频率/归位边界由 `ADR-NET-01` 落地。此契约同步纳入 ① §8。
- **设计层需求（→程基岩 `ADR-NET-01`）**：
  1. 托管快照频率（对接 ① 重连恢复 + ⑦ 断线跳过 tick）。
  2. 重连归位边界（`DOWNED`/`ALIVE` 状态还原，防跳变；**含 `DOWNED` 剩余窗口还原**）。
- **已拍板决策落点（用户，经主理人转交）**：
  - DOWNED 期间 **免疫补刀致死**（保 P4 友好）：见 §3 / §4。
  - 超时 → **`OUT`（本局观战，下局再战），MVP 不做永久死亡**：见 §3 / §4 / §5。
- **开放问题**：层数/Boss 阶段等数值 `待调`（见各 §4）。
