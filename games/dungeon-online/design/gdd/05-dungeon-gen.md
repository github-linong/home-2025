# GDD ⑤ 地牢生成系统（Dungeon Generation）
**路径**：`games/dungeon-online/design/gdd/05-dungeon-gen.md` ｜ 标记：`[MVP][P2]`
**依赖（systems-index §2）**：依赖 ③ 敌人与资源数据定义（L0）；被依赖 ⑥⑧⑫。
**循环依赖纪律 A（systems-index §2.3）**：本系统**只引用 L0 数据定义（敌人/资源类型 ID），绝不依赖敌人运行时（⑧）**；敌人运行时（L2）反向依赖本系统生成的刷怪点（L1）。本 GDD 代码/文档边界须白纸黑字标注此纪律。

## 1. 目的与支柱对齐
解决单局世界构造，闭合 探/下 循环，是 **P2「每局新谜题」的来源**（concept §1 P2：布局/敌人/资源每局变化）。间接服务 P3（可读布局）。设计红线：严守「固定模板 + 轻量随机」，不滑向程序化生成（属延展）；不引入经济/掉落（⑥ 负责）。

## 2. 依赖与上游接口（修订后，刷怪点表指向 §3 schema）
- **依赖**：③ 敌人与资源数据定义（L0，仅引用敌人/资源**类型 ID**）。
- **提供接口（被依赖方）**：
  - → ⑥ 资源与掉落：资源节点放置坐标（基于本系统布局）。
  - → ⑧ 敌人与 AI：**刷怪点实例数组 `SpawnPoint[]`（单一 schema 见 §3）**，供 ⑧ 运行时只读消费。
  - → ⑫ 进度与结算：楼层结构（层序列、Boss 房位置、出口）。
- **上游接口需求（→程基岩）**：确定性种子 + 布局快照，供 ① 服务器持有并重连恢复（systems-index §5 ⑤）。

## 3. 核心机制（修订后，新增刷怪点输出契约 + 纪律 A 字段级边界）
- **1 生物群系（余烬矿坑）**：固定房间拓扑**模板库** + 轻量随机（房间顺序、敌人点位、资源点、层间分支）。
- **确定性种子生成**：基于 `run_seed` 确定性产出布局（房间序列、刷怪点、资源点、楼层），服务器持有 seed + 布局快照供重连恢复（对接 ① 重连恢复）。同 seed 必产同布局。
- **房间图**：房间节点（战斗房/休息点/资源房/Boss 房/出口）+ 连接边；层间分支（轻量随机选路）。
- **层间休息点标记**：每层或每 N 层设休息点，作为"商(Regroup)"谈判窗口（不立独立安全屋系统，守 §2.4 范围纪律）。
- **纪律 A 落地**：本系统读取 ③ 的敌人/资源类型 ID 做放置，**不调用 ⑧ 敌人运行时任何逻辑**；⑧ 反向读取本系统生成的刷怪点。
- **刷怪点输出契约（单一 schema，纪律 A 字段级边界）**：本系统向 ⑧ 输出的刷怪点表为如下结构的**实例数组**，⑧ **仅读取这些实例，严禁反向调用本系统的布局/随机生成函数**：
  ```
  SpawnPoint {
    pos: vec2            // 世界坐标（px，32px tile 网格对齐；原点=地牢左上，x右/y下）
    enemy_type_id: str   // 引用 ③ 敌人原型表 ID（非运行时实例）
    wave: int            // 波次序号（同房间内 0 起；同 wave 敌人同时激活，便于编队/节奏）
    count: int           // 该点生成的敌人数量（同一 type_id 的集群规模，如杂兵 3–6）
  }
  ```
  - **坐标系**：世界像素坐标，与地牢碰撞层同基准；⑧/客户端不重算，直接消费。
  - **波次语义**：`wave` 仅表达"激活批次"序号，不携带行为逻辑；具体何时激活由 ⑧/⑫ 按房间进度决定（本系统不负责激活时序）。
  - **纪律 A 字段级边界**：⑧ 读取 `SpawnPoint[]` 实例数组；**不得** import ⑤ 的 `generate_layout()` / `roll_random()` / 房间模板等函数；⑤ 也**不得**在产出后回调 ⑧。单向：⑤ 产出 → ⑧ 消费。

## 4. 数值/平衡初稿（`待调`）
- 生物群系：1（余烬矿坑）。
- 单局楼层数：建议 **5–7 层**（目标单局 8–15min）。
- 房间模板库：固定 **6–10 套**，随机排列（待调）。
- 分支率：每层 **0–1 个**分支点（轻量随机，待调）。
- 刷怪点密度：每战斗房 **3–8 个**（按层递增，待调）。
- 资源点：每房 **0–2 个**（待调）。
- `run_seed`：64-bit，服务器生成并持有。

## 5. 状态机/流程
- 生成：收到 `run_seed` + 生物群系 ID → 选房间模板序列 → 按 seed 随机填敌人点位/资源点/分支 → 产出（布局图 + 刷怪点表 + 资源点表 + 楼层序列）。
- 运行时：玩家下行推进，逐层激活房间；Boss 房在末层。
- 重连：服务器持 seed + 布局快照，新客户端凭此重建（确定性保证一致，无需重生成）。

## 6. 联机/权威服务器影响
- 布局由服务器基于 seed 生成，权威；客户端仅接收布局数据。
- 确定性 seed 保证重连客户端重建一致布局（对接 ① 重连恢复）。
- 布局固定，不随玩家掉线变化（P4 无关）。

## 7. 可读性/UX 约束
- 布局须可读：房间连通性清晰；战争迷雾**并集**（①/⑬/程基岩）下"已探索/未知"以静态形状区分。
- 危险物（陷阱/机关）静态预警遵循 art-bible §7（P3 硬约束）。
- 色盲三重编码、阵营色纪律：资源节点用 GOLD 描边（art-bible §4），不混淆语义。
