## 0. 一句话定位

> 一张可共闯的武侠大地图 + 暗黑式词缀掉装 + 随机秘境副本，**纯合作、即开即玩、死亡低惩罚**的浏览器武侠刷宝 ARPG。

## 1. 游戏支柱（动词优先）

设计支柱是后续所有 GDD 与评审的"宪法"。以下 5 条均为**动词优先**（从玩家动作出发），且彼此不冲突、可同时成立。

| # | 支柱（动词优先） | 一句话诠释 | 否决什么 |
|---|----------------|-----------|---------|
| P1 | **共闯江湖** (Co-op First) | 玩家永远只能并肩打怪，不能互殴；同图即队友。 | 任何 PvP / 敌对玩法、抢怪惩罚性设计 |
| P2 | **拾装变强** (Loot & Build) | 成长主要靠暗黑式词缀装备驱动，每一件掉落都是 build 选择。 | 纯数值等级碾压、无随机性的固定装备 |
| P3 | **格挡反击** (Parry & Strike) | 网格节奏下的实时动作，格挡时机 > 无脑站桩输出。 | 纯自动战斗、无操作深度的放置刷怪 |
| P4 | **探入秘境** (Delve) | 大地图之外，入口连着服务端生成的随机副本，未知即爽点。 | 固定脚本副本、无重玩价值的静态地牢 |
| P5 | **即开即玩** (Instant Play) | 浏览器点开就进，游客也能玩；死亡不掉永久装，低挫败。 | 重养成门槛、死亡硬惩罚、强制登录墙 |

> 支柱冲突护栏：若某功能同时服务两条支柱且成本过高，**优先保 P1（共闯）与 P5（即开即玩）**，因二者是本作相对于竞品的差异点。

## 2. MDA 框架分析

### 2.1 Mechanics（机制层 — 规则与系统）
- 移动：网格步进（tile-based），tick 同步（复用 wander 的网格步进 + 房间广播）。
- 战斗：3–4 个小技能带 CD；格挡窗口 + 连招雏形（参考刀剑封魔录）；含 BOSS 战机制。
- 刷怪：单一公共地图内划分**安全区 / 刷怪区**；怪物定时复活；普通怪 + 精英（蓝怪/精怪）+ BOSS 三档。
- 掉装：装备带预定义**词缀（affixes）**；稀有度分档；暗黑式掉落；BOSS 必掉更好词缀。
- 地牢：地图某处"入口" → 服务端生成**独立随机实例**（seed 驱动），BOSS 置于深层。
- 养成：简单等级 + 装备双线；属性体系（力/敏/体 三系）。
- 持久化：Better Auth 登录落库（跨刷新保留角色与背包）+ 游客临时双模式。
- 社交：默认单房间、多人可见同图、可共打同怪（复用 chat 广播）；本期无正式组队 UI。

### 2.2 Dynamics（动态层 — 涌现行为）
- **精英/BOSS 围猎**：精英与 BOSS 刷新点天然成为玩家聚集地，陌生人临时扎堆共刷、共打 BOSS。
- **搭便车与互助**：无组队框架时，玩家靠"站在同一只怪的仇恨圈里"实现事实 co-op，"借刀杀怪"与"借怪练级"并存。
- **词缀套利**：相同怪物因掉词缀不同，玩家会产生"这只有没有出金"的复刷偏好，形成软性热点。
- **入口社交**：随机地牢入口成为事实上的"集合点"，玩家在此自发组队（即便无 UI）。
- **tick 走位博弈**：网格 + tick 同步下，玩家用卡位/拉扯制造输出窗口，形成可读的走位 dance。

### 2.3 Aesthetics（美学层 — 玩家获得的"乐趣"）
按 LeBlanc 八类乐趣映射：
- **Sensation（感官）**：武侠刀光剑影的动作爽快、词缀掉落的金光反馈。
- **Fantasy（幻想）**：身处江湖、一人一剑闯秘境的武侠代入。
- **Challenge（挑战）**：格挡时机、精英/BOSS/副本的 PvE 难度。
- **Fellowship（社交）**：与陌生侠客共闯、共刷、共清本/共打 BOSS 的陪伴感（P1 核心）。
- **Discovery（探索）**：随机地牢布局/词缀组合的未知惊喜。
- **Submission（收集）**：刷装、凑 build、堆战力的满足循环（P2 核心）。
- *Narrative / Expression*：本期弱（无正式剧情主线、无捏脸），远期再补。

## 3. 核心循环（动词优先法）

### 3.1 主循环（Macro Loop）
```
进入地图 → 探索刷怪区 → 击杀拾取 → 强化成长 → 再探索（更深处/更高档）
```
动词链：**进 · 探 · 杀 · 捡 · 强**。

### 3.2 子循环 A — 战斗微循环（Combat Micro）
```
走位 → 格挡/放技能 → 击杀(精英/BOSS) → 拾取词缀装 → 比对替换
```
动词链：**走 · 挡 · 杀 · 捡 · 换**。每次击杀都给"是否变强"的即时判断。

### 3.3 子循环 B — 秘境循环（Dungeon）
```
集合入口 → 进随机本 → 清场/抢精英 → 拾稀有/打BOSS → 出本回城
```
动词链：**聚 · 入 · 清 · 抢 · 出**。提供与主地图不同的密度与奖励节奏。

### 3.4 子循环 C — 养成循环（Progression）
```
升级/换装 → 解锁更高档怪 → 挑战更深本/BOSS → 获得更好词缀
```
动词链：**升 · 换 · 挑 · 得**。长线钩子，连接 P2 与 P5。

## 4. 玩家心理学 / 心流 / Bartle 适配

### 4.1 自我决定论（SDT）
- **自主性 Autonomy**：词缀 build 选择、去哪刷/进不进本/打不打 BOSS 的自由。
- **胜任感 Competence**：格挡时机掌握、连招熟练、战力可见成长、BOSS 击杀成就。
- **关系感 Relatedness**：co-op 共闯、chat 广播社交（P1 直接供给）。

### 4.2 心流（Flow）
- 清晰目标：清某刷怪区 / 击杀某精英 / 通关某本 / 击败 BOSS。
- 即时反馈：伤害数字、掉落金光、XP 条、技能 CD 回转。
- 难度匹配：网格 + tick 让操作"可读"，避免动作游戏常见的不可预测挫败；死亡低惩罚（P5）保住心流不断。

### 4.3 Bartle 玩家类型适配
| 类型 | 在本作如何被满足 | 备注 |
|------|----------------|------|
| Achiever（成就型） | 等级/战力分、通关副本、击杀 BOSS、凑齐稀有词缀 | 强契合 |
| Explorer（探索型） | 随机地牢布局、词缀组合空间、地图角落 | 强契合 |
| Socializer（社交型） | co-op、chat 广播、入口集合、共打 BOSS | 强契合（P1 核心） |
| Killer（杀戮型） | **本期不被满足**（无 PvP） | ⚠️ 风险点：见 §8（BOSS 战为 PvE 精通度替代出口之一） |

> 设计取舍：MVP 锁死"纯合作"（决策 A），因此 Killer 型玩家在本期缺位。用"PvE 精通度"（DPS/通关速度/无伤挑战/BOSS 首杀）作为 Killer 的替代出口，但需 Phase-2 再显式承接。

## 5. 范围分层

### 5.1 MVP（已锁定，不可改）
1. 单张公共地图（类征途凤凰城），不做多图。
2. 征途式刷怪：安全区/刷怪区划分 + 怪物复活 + 普通怪 + 蓝怪/精怪精英 + **BOSS（三档怪物）**。
3. 暗黑式掉装：定义好词缀（affixes）的装备掉落；BOSS 必掉更好词缀。
4. 随机地牢房间：地图"入口"进独立随机副本（服务端生成），BOSS 置于深层。
5. 默认单房间、支持多人（复用 chat 广播），暂不开放其他房间。
6. 单主角、剑侠情缘式单角色；无国战/宠物/操控他人。

### 5.2 Phase-2（候选扩展，需用户拍板优先级）
- 国战 / 跨阵营大型 PvE 事件（承接 Killer 与社交型）。
- 宠物 / 幻兽（魔域基因）—— 注意与"单主角"支柱的冲突，需重审。
- 多房间 / 多地图切换。
- 正式组队 UI（邀请/队伍框架/队伍 buff）。
- 世界 Boss（跨服/全图定时）。
- 打造系统 + 宝石镶嵌（刀剑封魔录 / 秦殇基因）。
- 五行 / 属性深度（秦殇基因）。
- 排行 / 公会 / 交易。

### 5.3 远期（愿景）
- 跨服、赛季制、经济交易系统。
- UGC 地牢编辑器。
- 武侠剧情主线（秦殇式暗黑历史叙事）。

## 6. 视觉锚点（给 art-director）

> 本节为**方向性关键词 + 参考描述**，不写最终美术规格。具体色板/线框/资产清单由 art-director 另出 art-bible。
> **已对齐美术**：以下 6 项视觉决策已由 art-director 在 Phase-2 确认，全作锁定，GDD 与之冲突以本条为准。

- **总体调性**：水墨像素（ink-wash pixel）风 × 暗黑写实光影。俯视 2D canvas（决策：客户端俯视 2D，**48px 网格**）。
- **关键词**：水墨像素、俯视、网格可读、墨青 + 朱红 + 暗金、阴翳感、刀剑冷光。
- **参考图描述**：
  - 场景：剑侠情缘 1 的市镇/野外（青砖、灯笼、竹林、驿站），但俯视网格化、像素化。
  - 怪物：刀剑封魔录的"封魔"味（被煞气侵蚀的精怪、蓝光的精怪）＋ 暗黑式地牢敌役；BOSS 为体型显著更大的异象首领。
  - 地牢：暗黑破坏神式随机房间（石墙、火把、符文门），但用水墨笔触弱化写实质感。
  - 装备掉落：暗黑式金光/词缀色环（白→蓝→金→暗金）。
- **分区可读（已对齐美术）**：安全区用**暖色**（灯笼、祥和青砖），此为"**暖 = 安全**"的**语义反转**（刻意背离暗黑奇幻以暖表危险的惯例）；刷怪区/危险区沿用 `DANGER` **8%** 色标（阴翳、煞气紫/墨），俯视图一眼可辨（支撑 P1 可读性与新手导航）。
- **动作表现**：格挡需明显的"兵刃相交"火花/顿帧（支撑 P3 格挡反击的手感反馈）。
- **地牢入口（已对齐美术）**：入口表现为**裂隙异象漩涡**视觉，作为全图集合点与秘境召唤的强识别锚。

## 7. 系统拆解初稿（概念层）

> 仅给出系统目标、机制要点、关键数据草图与依赖；逐系统八节 GDD 见 `design/gdd/`。

### 7.1 移动系统（grid-step）
- **目标**：可读、可预测的实时移动；服务端权威防作弊。
- **机制**：tile 网格（**48×48px/格**，已对齐美术水墨像素），tick（建议 10–15 tick/s）广播位置；点击/方向键触发步进。
- **依赖**：ws 网关、房间广播（wander）。
- **数据草图**：`moveSpeed = baseTiles/tick`；碰撞用 grid occupancy 校验。

### 7.2 战斗系统（技能 CD / 格挡 / 连招雏形）
- **目标**：3–4 个小技能带 CD；格挡时机 > 站桩；连招雏形提供操作深度；含 BOSS 战机制。
- **机制**：技能槽 3–4，各自 CD；格挡为"受击前 N ms 内输入"的窗口判定；连招 = 特定技能顺序触发额外效果（雏形，不强制）；BOSS 具备阶段/特殊技。
- **伤害公式草图**（标单位）：
  ```
  Damage(final) = max( 1 , ATK_eff × SkillMult − DEF_eff )        [HP 点]
  ATK_eff  = BaseATK × (1 + ΣAffix_ATK% + STR × k_str)            [攻击点]
  DEF_eff  = BaseDEF × (1 + ΣAffix_DEF% + VIT × k_vit)            [防御点]
  格挡成功 = 伤害 × (1 − ParryReduction) ，并触发硬直/反伤        [ParryReduction≈0.6]
  ```
- **依赖**：移动系统（站位）、属性系统、掉装系统（词缀供给数值）、刷怪系统（BOSS 目标）。
- **⚠️ 风险**：网格 + tick 下"格挡窗口"需与服务端判定对齐，延迟高时手感崩坏（见 §8）。

### 7.3 刷怪系统（安全区 / 刷怪区 / 复活 / 精英 / BOSS）
- **目标**：征途式节奏——安全区喘息、刷怪区练级、精英/BOSS 制造热点。
- **机制**：
  - 地图静态分区（安全区标记 + 刷怪区标记）。
  - 刷怪点按 `respawnTimer` 复活普通怪（建议 30–60s）。
  - 精英（蓝怪/精怪）按更低频率 + 更高词缀掉落生成。
  - BOSS：极低频率/固定点位生成，高 HP/ATK，必掉更好词缀装（见 §7.4）。
- **数据草图**：`eliteChance ≈ 5%`、`bossChance` 固定点位按长周期刷新；精英 HP/ATK ≈ 普通 ×3，BOSS HP/ATK ≈ 普通 ×10。
- **已对齐美术**：安全区用暖色（灯笼/祥和青砖），此为"暖=安全"语义反转（背离暗黑奇幻以暖表危险的惯例）；刷怪区/危险区沿用 `DANGER` 8% 色标，俯视图一眼可辨（支撑 P1 可读性与新手导航）。
- **依赖**：地图数据、掉装系统（精英/BOSS 必掉词缀装）、持久化（击杀计数/任务）。

### 7.4 掉装系统（词缀 / 稀有度）
- **目标**：暗黑式随机词缀驱动 build（P2 支柱）。
- **机制**：
  - 稀有度分档：**普通(白) / 精良(蓝) / 稀有(金) / 暗金(传奇)**。
  - 词缀池（MVP 初版，小池）：力/敏/体、ATK%、DEF、暴击率、攻速、吸血、元素伤（金木水火土选 2–3）。
  - 掉落规则：普通怪低概率掉白/蓝；精英必掉且带 2–4 条词缀、稀有度加权；**BOSS 必掉且稀有度加权更高（≥金，暗金概率提升）**。
- **数据草图**：
  ```
  dropChance(普通) ≈ 0.30 ；dropChance(精英) = 1.0 ；dropChance(BOSS) = 1.0(加权更高)
  affixCount: 白=0~1, 蓝=2, 金=3~4, 暗金=4 + 1 专属
  ```
- **依赖**：刷怪系统、属性系统、持久化（入库）。
- **⚠️ 风险**：词缀池过大 → 认知过载（见 §8）；需 tooltip 分层。

### 7.5 随机地牢系统（入口 + 实例）
- **目标**：入口进服务端生成的独立随机副本（决策 E），BOSS 置于深层。
- **机制**：地图固定"入口"格（**裂隙异象漩涡**视觉，已对齐美术）→ 触发实例生成（seed + 房间模板随机拼接）；副本内独立刷怪/掉装；可选分层，BOSS 置于深层；出本回安全区。
- **数据草图**：`instanceSeed = hash(serverTick + entranceId + partyTag)`；房间数 5–12，深层放置 BOSS。
- **依赖**：刷怪系统、掉装系统、持久化（副本进度临时态）。
- **⚠️ 风险**：多人同本时实例归属/广播域需明确（默认单房间复用 chat 广播，但副本应独立域）。

### 7.6 持久化系统（登录 + 游客）
- **目标**：跨刷新保留角色与背包（决策 D）；游客临时双模式。
- **机制**：Better Auth 登录 → 角色/背包/等级写库；游客 → 临时会话，退出可丢（或限时保留）。
- **依赖**：认证系统、DB schema。
- **⚠️ 风险**：游客与登录账号的数据合并/迁移策略需定义（避免重复刷装舞弊）。

### 7.7 认证系统
- **目标**：Better Auth 集成，支撑登录落库与游客双模式（决策 D）。
- **机制**：登录态下发 token；服务端据此加载/保存角色；游客发临时匿名标识。
- **依赖**：Better Auth、持久化系统、ws 网关鉴权。

## 8. 设计理论评审点 / 已知风险

> 以下为概念阶段即可识别的红线与风险，Phase-2 GDD 必须逐条回应。

### 8.1 四大设计红线（发现即标注）
- **主导策略 Dominant Strategy**：若某技能/CD 组合明显最优 → 需平衡（如格挡无敌帧过长会废掉其他技能）。*监控点：战斗系统 GDD。*
- **经济失衡 Economy Imbalance**：词缀装只产不出（无 sink）→ 通胀。*缓解：MVP 宽松可接受，Phase-2 加打造消耗/交易税。*
- **认知过载 Cognitive Overload**：词缀池 + 属性 + 稀有度同时堆给新手 → 劝退（违背 P5）。*缓解：tooltip 分层、MVP 小词缀池、白装无词缀。*
- **支柱漂移 Pillar Drift**：任何"为留存加 PvP/加养成墙"的诱惑都会侵蚀 P1/P5。*护栏：§1 否决表。*

### 8.2 已知风险清单
