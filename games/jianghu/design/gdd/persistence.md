# GDD · 持久化系统（登录落库 + 游客临时双模式）

> 系统编号：SYS-06　|　作者：design-strategist　|　版本：v0.1（Phase-2 初稿）
> 关联概念：concept.md §7.6、§8.3（决策 D：登录落库 + 游客双模式；③ 双线养成；④ 死亡不掉装）

---

## ① 目标与范围
- **目标**：跨刷新保留角色与背包（决策 D）；游客临时双模式；支撑双线养成数据落地。
- **范围（含）**：角色（等级/EXP/属性/位置）、背包（词缀装备）、自动保存、游客会话隔离。
- **范围（不含）**：认证协议（归认证）、战斗结算（归战斗）、掉落生成（归掉装）。

## ② 核心机制
- **登录玩家**：Better Auth 身份 → 加载 `Character` + `Inventory`；定时/下线保存。
- **游客**：生成临时会话（内存或限时存储），数据**不写持久库**；退出即弃（或限时保留）。
- **双线养成落地**：等级 + EXP 按 `XP_req(L)=50·L^1.5`（取整）推进；属性 STR/DEX/VIT 与词缀装备共同构成战力。
- **死亡不掉装**：死亡仅回安全区，背包/装备保持不变（决策④）。
- **保存时机**：定时自动保存（间隔）+ 关键事件（升级/拾取/下线）即时保存。

## ③ 数据模型 / 状态
```
Character {
  userId, level, exp,
  attrs: { STR, DEX, VIT },     ; 三系 (已去"内")
  pos: {gx, gy},                ; 落库位置(断线恢复)
  createdAt, updatedAt,
}
Inventory { userId, items: [Item×≤60], capacity=60 }
GuestSession { tempId, data: {level,exp,attrs,items}, ttl }
```
- DB：关系表或文档；Better Auth 用户表外键关联 `Character`。

## ④ 与其他系统依赖
- **认证系统**：提供 `userId` 或 `guestId`，决定加载/保存路径。
- **掉装系统**：掉落物品写入 `Inventory`（仅登录玩家持久；游客仅会话）。
- **战斗 / 移动**：状态（HP/位置/等级影响）经本系统落库。
- **随机地牢**：副本进度为临时态，不长期落库。

## ⑤ 边界与异常
- **游客不入库**：游客掉落/进度仅会话内，退出即弃（防刷装舞弊，concept §8.2）。
- **并发保存**：同账号多连接 → last-write 或乐观锁，避免互相覆盖。
- **DB 不可用**：降级为游客模式（本地内存），恢复后提示未保存（不丢登录态 token）。
- **背包上限**【已决·主理人推荐】：满 60 后溢出物品落脚下地面（TTL 自动消失），无邮件系统。与 loot §⑤ 一致。
- **数据迁移**：游客→登录**明确不合并**（避免重复刷装）；如需保留需用户显式操作（Phase-2）。

## ⑥ 平衡初值
- 自动保存间隔 `30s`；关键事件即时保存。
- 游客会话 `ttl`：浏览器关闭即弃（或内存会话）。
- 背包上限 `60` 格；等级无上限（曲线放缓）。
- `XP_req(L) = round(50 × L^1.5)`。

## ⑦ 可测试性 / 验收
- **刷新保留**：登录玩家刷新后等级/背包/位置一致（断言逐字段相等）。
- **游客隔离**：游客刷新后数据清空，且不写入持久库（断言 DB 无记录）。
- **并发保存**：双连接同时保存，最终状态一致、无丢失。
- **掉装入库**：登录玩家拾取后 DB `Inventory` 含该 Item；游客不含。
- **验收标准**：100 次刷新角色零丢失；游客零泄漏入库。

## ⑧ 开放问题 / 风险
- **游客→登录迁移**【已决·主理人推荐】：明确**不合并**（丢弃游客进度），与 auth §⑧ 一致；未来是否提供绑定迁移待 Phase-2+ 产品决策，本期不实现。
- **多设备（单角色多端）**【已决·主理人推荐】：采用「后连接顶替（last-wins）」，新连接覆盖旧会话，与 auth §⑤ 一致。
- **数据版本迁移**：属性从四系（含内）改为三系，旧档迁移需脚本（本期新项目无旧档，影响低）。
- **背包满策略**【已决·主理人推荐】：溢出落脚下地面（TTL 自动消失），无邮件，与 loot §⑤ / persistence §⑤ 一致。
