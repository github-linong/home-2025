# GDD · 认证系统（Better Auth 接线）

> 系统编号：SYS-07　|　作者：design-strategist　|　版本：v0.1（Phase-2 初稿）
> 关联概念：concept.md §7.7、§8.3（决策 D：登录落库 + 游客双模式）

---

## ① 目标与范围
- **目标**：Better Auth 集成，支撑登录落库与游客双模式（决策 D）；为 ws 连接提供身份鉴权。
- **范围（含）**：登录流程（token 下发）、游客匿名标识、ws 连接鉴权、身份→持久化加载、登出。
- **范围（不含）**：角色数据存储（归持久化）、第三方 OAuth 细节（Phase-2）。

## ② 核心机制
- **登录流程**：Better Auth 校验凭证 → 下发 `token`（含 `userId`、`expiresAt`）→ 客户端持 token 建立 ws 连接。
- **游客**：无凭证 → 服务端发临时匿名 `guestId`（随机 UUID），不创建持久用户；仅会话有效。
- **ws 鉴权**：连接握手携带 token/guestId → 服务端校验 → 通过后交由持久化加载角色（登录）或建临时会话（游客）。
- **重连**：token 未过期 → 直接恢复；过期 → 重新登录或降级游客。
- **登出**：撤销 token，释放会话。

## ③ 数据模型 / 状态
```
AuthSession {
  token, userId | guestId,
  role: 'user' | 'guest',
  expiresAt,
}
BetterAuthUser { id, email?, createdAt, ... }   ; 由 Better Auth 管理
```
- 密钥/盐由 Better Auth 托管；`guestId` 服务端生成，不可猜测。

## ④ 与其他系统依赖
- **Better Auth**：核心认证能力（登录/会话/校验）。
- **持久化系统**：登录后加载/保存 `Character`/`Inventory`；游客走临时会话。
- **ws 网关**：连接握手鉴权（复用 wander/chat 的连接层）。
- **移动 / 战斗 / 刷怪 / 掉装 / 地牢**：均依赖已鉴权身份进入对应系统。

## ⑤ 边界与异常
- **token 过期**：刷新或重登；游客无过期概念（会话结束即弃）。
- **游客无密码**：不暴露任何凭证接口；禁止游客尝试持久写。
- **恶意连接**：无有效 token/guestId → 拒绝握手（防作弊/资源耗尽）。
- **同账号多连接**【已决·主理人推荐】：采用「后连接顶替（last-wins）」，新连接覆盖旧会话，与 persistence §⑧ 一致。
- **握手超时**：`5s` 内未鉴权 → 断开。

## ⑥ 平衡初值
- `token TTL = 7d`（可刷新）；游客 `guestId` 随机 UUID v4。
- 握手超时 `5s`；并发鉴权限流（防爆破）。
- 登录与游客入口并存，用户可一键以游客进入（护 P5 即开即玩）。

## ⑦ 可测试性 / 验收
- **两条路径**：登录 token 进入 → 加载持久角色；游客 guestId 进入 → 临时会话；均断言可正常游戏。
- **鉴权失败**：无效 token → 握手拒绝（断言无进入）。
- **过期**：token 过期 → 拒绝/重登（断言不越权）。
- **游客隔离**：游客会话不产生 Better Auth 用户记录（断言 DB 无新增）。
- **验收标准**：两种模式进入成功率 100%；非法连接 100% 拒绝。

## ⑧ 开放问题 / 风险
- **第三方登录**（Google/微信等）：Phase-2 扩展，需 Better Auth 插件。
- **账号绑定**【已决·主理人推荐】：游客→登录**不合并**（丢弃游客进度），与 persistence §⑧ 一致；本期不提供绑定迁移。
- **反作弊**：加速/篡改需 ws 层校验（与程基岩对齐移动/战斗服务端权威）。
- **单角色多端**【已决·主理人推荐】：后连接顶替（last-wins），与 persistence §⑧ / auth §⑤ 一致。
