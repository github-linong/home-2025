## 0. 审计方法
- 逐类对照「art-bible §4/§5/§7/§8 + asset-specs §1–§5 + accessibility §1 特性矩阵」，核对现有 `draw*` 函数实现。
- 评级定义：
  - **够用**：已达 MVP 可读，无阻塞，暂不动。
  - **可加强**：能玩但明显短板（辨识度/一致性/状态清晰度），建议补。
  - **需重做**：与美术圣经/规格严重偏离，影响可读性、可访问性或风格统一，须纠正。
- 每条补强给「程序化画法（形状/配色/动效）+ 成本（低/中/高）+ 优先级（P0/P1/P2）」。

## 2. 补强清单（P0 / P1 / P2）

> 原则：**视觉一致性 > 数量**；所有补强优先走**程序化 Canvas**（零资源、风格一致、确定性），仅「屏幕外/宣传/图鉴」类才考虑生图（见 §3）。

### 2.1 P0（核心循环辨识度 + 可读性，立即可做，纯 draw 改动）

**P0-1 精英视觉重做 → 对齐蓝怪规范**
- 方案：`drawShadowAssassin` 主色由暗紫 `#4a2a5e` 改为**钢蓝 `#5F8FB0`**（高光 `#8FB8D8`）；兜帽/披风剪影保留，但叠加**常驻青环 `#5FD0E0`**（`ctx.arc` 1.5px 半透明，恒定不脉动）；头顶加**王冠/双剑图标**（新增 `drawEliteIcon()`，≥16px、白 `#fff` + 黑 `#111` 双描边，王冠=3 尖角路径或双剑=两斜线交叉）。
- 三重编码：钢蓝 tint（色相）+ 青环（上下文）+ 图标（形状），不靠单一颜色——满足 accessibility #4。
- 成本：**低**。优先级：**P0**。

**P0-2 BOSS 视觉重做（体量 + 图标 + 常驻 aura 三项，阶段化后置）**
- 方案：
  - **体量**：`drawEnemy` 中 BOSS `size` 由 `52` → `≥90`（屏幕空间，约普通怪 3×+）；`drawTroll` 拆多部件：头（巨口+獠牙）×躯干 ×双肩甲 ×双巨拳 ×脊柱骨刺 ×下肢，墨线 2px 轮廓 + 去饱和深棕主色。
  - **妖纹图标**：新增 `drawBossIcon()`（头顶常驻，≥20px，白黑双描边，妖纹=不对称回纹/独眼），替代现有金色「BOSS」纯文字（文字可保留作冗余，accessibility #13）。
  - **常驻异象 aura**：BOSS 脚下加**恒定 RIFT 紫 `#7B5CC4` + RIFT_TEAL `#3FB6B0` 漩涡 + 地面裂痕**（不脉动，与精英青环强度拉开层级）。
  - 阶段色/阶段切换归 P2。
- 成本：**中**。优先级：**P0**（体量+图标+aura 为不可砍底线，阶段化可后置）。

**P0-3 阵营色 P1–P4 落地（多人区分）**
- 方案：引入 `factionColor(ownerId)`（ownerId 哈希 → `#4CB5F5`/`#9B7BE8`/`#E86FB0`/`#6FD68A`，或服务端下发 seatIndex）。落地三处：
  - `drawWuxiaHero` 增加**阵营色描边**（`ctx.strokeStyle = factionColor`，2px ink-outline 外圈）；
  - `drawNameplate` 边框与名字用阵营色（替代当前暖橙统一）；
  - `drawHpBar` 底条用阵营色（替代绿/橙/红血条底，血条前景仍按 HP 比例变色但底是阵营色）。
- 本地玩家仍保留金色圈标识（当前已实现），与阵营描边不冲突。
- 成本：**低**。优先级：**P0**（accessibility #2/#6 硬底线）。

**P0-4 telegraph 三重编码 + 色盲斜纹**
- 方案：`drawTelegraph` 增加：
  - **形状图标**：DANGER 红区内部画白色危险图标（陷阱=十字、AOE=同心三角、弧=扇形箭头），≥16px 白黑双描边；
  - **色盲斜纹叠加**：危险区叠加 45° 白色半透明斜纹（`setLineDash` 或循环细线，accessibility #11 可选开关）；
  - **形状多样化**：除圆/环外，增加 AOE 填充变体（已有 shape1）、弧（扇形 `ctx.arc` + `lineTo` 收口）、矩形陷阱格。
- 保留 DANGER `#E5484D` 豁免纪律（自身亮度 + 同屏数量预算，art-bible §2.6）。
- 成本：**低**。优先级：**P0**。

### 2.2 P1（Standard 增强：动画 + 一致性 + 状态）

**P1-1 敌人/玩家动画帧（程序化时间驱动，无需真帧图）**
- 方案：
  - **idle 呼吸**：`scale(1 + 0.02*sin(t/400))`；
  - **walk 摆动**：躯干小幅左右摆（`rotate(0.04*sin(t/180))`）+ 腿部/披风相位摆动；
  - **attack 挥砍**：攻击瞬间武器路径旋转 ±30°（`drawWuxiaHero` 剑绕身旋转，山贼短刀、狼扑咬前倾）；
  - **受击后仰**：受击 150ms 内 `rotate` 后仰 + 位移 -2px（配合现有闪白）。
- 成本：**中**。优先级：**P1**。

**P1-2 玩家装备剪影变体（刀/剑/枪/扇）**
- 方案：`drawWuxiaHero` 增加 `weapon` 参数，武器层独立绘制：剑（现直线）、刀（单刃宽刃）、枪（长杆+尖）、扇（半圆展开）。多人靠「阵营色 + 装备剪影 + 名牌」三件套区分（art-bible §4）。
- 成本：**中**。优先级：**P1**。

**P1-3 稀有度色档对齐六档 + 掉落 icon 扩展**
- 方案：`RARITY_COLORS` 由 4 档改为 6 档（白 `#D8D2C4` / 绿 `#5FA85F` / 蓝 `#4C7FD6` / 紫 `#9B5FD6` / 橙 `#F2A03C` / 红 `#C8324A`，art-bible §2.5）；`RARITY_NAMES` 对应 白/绿/蓝/紫/橙/红；`drawLootIcon` 3 槽扩展为按词缀类型（或保留 3 槽 + 词缀 chip 色）。
- 成本：**低**。优先级：**P1**。

**P1-4 HUD 风格统一（暗黑武侠 · 分快赢/结构两档）**
- 方案（CSS 快赢，低风险先做）：
  - **字体**：引入 `Zpix`/`ZCOOL XiaoWei`（@font-face + `font-display: swap`，fallback system-ui），HUD 全量替换；
  - **技能栏**：`.abtn` 圆角石面格（内阴影石纹渐变 + 1px 暖灰描边）；冷却改为**环形遮罩**（CSS `conic-gradient` 遮罩或 Canvas 环形，随 CD 比例画弧）；
  - **血条**：`drawHpBar` 加**体/内力第二条**（HP 红 + 体青 `#5FD0E0`），底用阵营色 + 白描边；
  - **背包**：暗色卷轴/竹简面板（暖棕木纹底 `#4A3826` + 竹节分隔线）；词缀用**六档边框 chip**（白/绿/蓝/紫/橙/红 2px 边框 + 图标 + 文字）；
  - **掉装提示**：底部 toast → 右侧滚动 ticker（稀有度色 + 图标 + 文字），传说/神话居中横幅 + 辉光。
- 成本：**中**。优先级：**P1**。

**P1-5 状态表现补强（受击/格挡/倒地/无敌/前摇）**
- 方案：受击后仰（P1-1）；格挡已有青环+「格挡！」✓；倒地已有骷髅+旋转 ✓；无敌已有 alpha 呼吸 ✓；前摇已有红头脉动+缩身 ✓——**补强前摇**：普通怪前摇红头 → 升级为「头顶 DANGER 感叹号图标 + 武器抬起 + 短暂高亮轮廓」，与 telegraph 静态圈协同（accessibility #5）。
- 成本：**低**。优先级：**P1**。

### 2.3 P2（打磨 + 反馈高潮 + 可访问性工程项）

**P2-1 反馈动效高潮（击杀/暴击/升级/开箱）**
- 方案：
  - **暴击视觉**：飘字放大 1.6× + 橙金 `#F2A03C` 辉光 + 屏幕微震（区分普通命中白/黄飘字）；当前仅音效无视觉。
  - **击杀**：现有粒子 ✓，补「墨点碎裂」——敌人消散为墨色扩散点（水墨像素语言，替代纯红方块）。
  - **升级**：现有全屏淡金+金环 ✓，补「升级！Lv.N」居中横幅（当前仅 toast）。
  - **开箱**：`drawChest` 加开盖动画（箱盖 `rotate` 打开）+ 物品喷出 + 金色爆发闪光 + 稀有度光柱脉冲升级。
- 成本：**中**。优先级：**P2**。

**P2-2 精英/BOSS 登场异象 + BOSS 阶段化**
- 方案：精英登场加 RIFT 紫青脉冲 + 地面裂痕 + 短暂暗角；BOSS 登场加全屏轻暗 + 妖纹脉冲；BOSS 阶段切换（VOID 紫 → RIFT 青 → DANGER 红预警态）轮换 aura 色 + 轮廓光 + 文字提示（accessibility #13）。
- 成本：**中/高**。优先级：**P2**。

**P2-3 可访问性工程项（reduced-motion / 色盲开关 / 字体缩放）**
- 方案：`reduced-motion` 关装饰粒子/抖动/屏震，保留静态 telegraph SHAPE；色盲模式开关切换 alt 调色板或斜纹叠加（P0-4 斜纹复用）；字体缩放 1.0×–1.5× 整数档。**归属工程为主**，美术供图标 + alt 调色板（accessibility §5 已标「待引擎」）。
- 成本：**中（工程）**。优先级：**P2**。

## 3. 生图（ImageGen） vs 程序化 判断

| 资产 | 判断 | 理由 |
|---|---|---|
| 玩家/普通敌人/精英/BOSS **游戏内剪影** | **程序化就够** | 俯视小尺寸 + ink-pixel 有限调色板下，几何路径 + 阵营/图标/aura 已能保证一致性与辨识度；生图反引入风格漂移 + 加载成本 + 色盲不可控 |
| 掉落/宝箱/入口/telegraph **图标与特效** | **程序化就够** | 都是小尺寸图标/几何光效，程序化可 100% 对齐语义色与三重编码 |
| HUD 全部元素 | **程序化/DOM 就够** | 石面格/环形冷却/竹简面板均可用 CSS/Canvas 画，无需位图 |
| VFX（刀光/剑气/震荡/斩杀/登场） | **程序化就够** | 现有 4 技能光效已验证，几何+渐变+阴影足够 |
| **BOSS 全身立绘 / 妖王概念图**（图鉴/loading/宣传） | **值得生图** | 复杂细节（鳞甲/妖纹/毛发/多臂）非小尺寸剪影能承载；仅用于屏幕外静态展示 |
| **封面/营销 hero 图**（key art，替换/增强现有 `/heroes/demo/jianghu.webp`） | **值得生图** | 需「灯尽处」水墨暗黑武侠氛围 + 侠客/灯火/妖氛构图，宣传向非 gameplay |
| **环境氛围背景**（远山/断壁/城池灯火，splash/加载屏） | **值得生图** | 复杂水墨笔意与光影，程序化成本高 |
| 装备/词缀图标（物品 icon 全身/俯视） | **偏程序化（或像素生图后统一）** | 若走 ink-pixel 像素风，程序化/像素级生成更一致；生图仅适合「写实水墨宣传向」并需后处理降饱和 + 墨线统一 |

**结论**：**游戏内可玩资产 100% 程序化**（保持风格一致 + 零资源 + 确定性 + 色盲可控）；**生图仅用于「屏幕外 / 宣传 / 图鉴 / loading」的复杂静态 2D 图**（BOSS 全身立绘、封面 key art、环境氛围背景），且生图后须统一降饱和 + 墨线描边对齐 ink-pixel 风格，避免与游戏内剪影割裂。

## 4. engineering-lead 实现优先级建议

**P0 先做（纯 draw 函数改动，零资产加载，低风险，立即可落地）**：
1. **精英蓝怪化**：`drawShadowAssassin` 主色改钢蓝 `#5F8FB0` + 常驻青环 `#5FD0E0` + 王冠/双剑图标（P0-1）。
2. **BOSS 体量 + 图标 + aura**：`drawEnemy` BOSS size `52→≥90`；`drawTroll` 多部件；`drawBossIcon` 妖纹 + 常驻 RIFT 紫青异象 aura + 地面裂痕（P0-2）。
3. **阵营色 P1–P4**：`factionColor(ownerId)` 落地描边/名牌/血条底（P0-3；需工程确认 ownerId 可用或服务端下发 seatIndex）。
4. **telegraph 三重编码**：形状图标 + 白色斜纹叠加 + 形状多样化（P0-4）。
