### 解答思路

浏览器是否下载文件，除了看前端 `<a>` 标签本身的属性，还会参考服务端响应头。可以从两方面入手：给 `<a>` 标签加 `download` 属性，同时让服务端返回 `Content-Disposition: attachment` 响应头。

### 示例代码

```html
<a href="a.mp4" download>下载视频</a>
```

```
Content-Disposition: attachment; filename=a.mp4;
```

### 详细说明

- `<a>` 标签的 `download` 属性可以提示浏览器将链接资源保存到本地，而不是导航打开，但该属性只在同源资源下必然生效，跨域资源浏览器可能仍会忽略。
- 更可靠的方式是让服务端在响应头中设置 `Content-Disposition: attachment; filename=xxx.mp4`，这会明确告诉浏览器该响应应作为附件下载，而不是当作可播放的内容直接渲染，这种方式对同源、跨域都生效。
- 两者可以同时使用：`download` 提升同源场景下的体验，`Content-Disposition` 从服务端层面保证下载行为的一致性。

### 小结

要让 mp4 链接点击后触发下载而非直接播放，最稳妥的做法是服务端设置 `Content-Disposition: attachment` 响应头，前端可配合 `<a download>` 属性一起使用。
