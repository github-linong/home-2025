### 解答思路
`for` 循环如果没有用 `{}` 包裹循环体，默认只会把**紧跟着的下一条语句**当作循环体；一旦把这条语句注释掉了，实际的循环体就变成了原本以为在循环外的下一行代码。

### 示例代码
```js
// 容易踩坑的写法：没有花括号，循环体只包含一条语句
for (let i = 0; i < 10; i++)
  // doSomething(); // 被注释掉之后，下面这行反而变成了循环体
  console.log(i);
```

修正方式：无论循环体有几条语句，都显式加上 `{}`：
```js
for (let i = 0; i < 10; i++) {
  // doSomething();
  console.log(i);
}
```

### 详细说明
- JS（以及 C 系语言）中 `for`/`if`/`while` 等语句在没有 `{}` 时，只会把紧接着的**一条**语句纳入控制范围。
- 当注释掉了原本紧跟在 `for` 后面的那一条语句，解释器会自动把下一条未注释的语句当作循环体，导致行为和预期（循环体是原来那一大段代码）完全不同。
- 这是经典的隐藏 bug 来源，很多团队的代码规范会强制要求所有控制语句都必须加 `{}`，即使循环体/条件体只有一行，也是为了从根源上避免这种问题。

### 小结
省略 `{}` 的控制语句只会把下一条语句纳入范围；养成给所有 `for`/`if`/`while` 加花括号的习惯，可以避免注释代码时引发的隐蔽 bug。
