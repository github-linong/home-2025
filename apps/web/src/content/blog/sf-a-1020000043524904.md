### 解答思路
这几个比较结果都是 `==` 隐式类型转换规则导致的：只要比较的两边类型不同，引擎会按固定顺序把一方（或双方）转换成基本类型再比较。而 `[] != []` 比较的是两个不同的对象引用，永远不相等（无论内容是否相同）。

### 示例代码（如有代码）
```js
console.log(34 == '034');   // true，字符串被转成数字比较
console.log(52 == '0x34');  // true，'0x34' 会被解析为十六进制数字 52

// 用 Proxy 观察对象转基本类型时的属性访问顺序
const a = new Proxy([], {
  get(obj, key) {
    console.log('proxy', 'get', '1', key, obj[key] instanceof Function ? obj[key]() : obj[key]);
    return obj[key];
  },
});
const b = new Proxy([], {
  get(obj, key) {
    console.log('proxy', 'get', '2', key, obj[key] instanceof Function ? obj[key]() : obj[key]);
    return obj[key];
  },
});

console.group('a == !b');
console.log(a == !b);
console.groupEnd('a == !b');

console.group('1 + a');
console.log(1 + a);
console.groupEnd('1 + a');

console.group("'1' + a");
console.log('1' + a);
console.groupEnd("'1' + a");

console.group('a + 1');
console.log(a + 1);
console.groupEnd('a + 1');

console.group("a + '1'");
console.log(a + '1');
console.groupEnd("a + '1'");
```

### 详细说明
- 如果比较双方类型相同（比如都是对象引用），`==` 和 `===` 行为一致，`[] != []` 比较的是两个不同数组对象的引用，因此为 `true`（不相等）。
- 如果类型不同，会触发类型转换：对象会先尝试 `Symbol.toPrimitive`，没有的话依次调用 `valueOf`、`toString` 转成基本类型；`[]` 转成基本类型后是空字符串 `""`；再和 `0` 比较时，字符串又会被转成数字 `0`。这样就能推出 `[] == "" == 0` 成立的链条。
- 表达式的运算符优先级也需要注意，混合使用 `==`、`+`、`!` 等操作符时，转换顺序会影响结果，遇到不确定的情况建议加括号或直接打印中间结果验证。
- 日常业务代码中，建议始终使用 `===` 做严格类型比较，配合 TypeScript 静态类型检查，基本可以避免这类隐式转换带来的怪异行为。
- 延伸阅读：[MDN - JavaScript 数据类型和数据结构](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Data_structures)。

### 小结
这几个等式的根源是 `==` 的隐式类型转换规则（对象 → 基本类型 → 统一类型再比较），而 `[] != []` 属于对象引用比较，与前面的转换规则无关。实际开发中优先使用 `===` + TypeScript，能从根本上规避此类问题，这类题目更适合作为面试考察类型转换规则理解程度的题目。
