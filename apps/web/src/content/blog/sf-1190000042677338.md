往年的我早早就参与了活动，今年不知道为什么，直到 2023.01.09 原来这就是答案。虽然果只有一个，但是因会有很多可能，不管怎么说反正是润

## 工作

22 年很累，整个人都扑在了业务上（无穷无尽）。做的方向大概分为两部分（通用服务、流程编排） ，整体还是对内提供技术服务。因为某些原因，整体来说还是遗憾较多，可以整理一下各个方向的产出收获（flag1: 整理之后发文）
- 
Vue2 组件支持 Vue3 使用。 22 年 Vue3 项目逐渐多了，但是部分基础服务组件还没有升级 vue3 ，导致业务开发进度阻塞。在这个阶段做了一些过渡方案，这里简单说一下都有什么，整理的话等下一篇文章
直接撸一套 Vue3
- Vue2 升 2.7，然后升级语法，分开编译
- 组件市场
- 「我们部分组件用了这个」打包加入 Vue2 依赖，然后封装。实现框架无关
- vue2 render 转 vue3 render
- 性能优化。就不展开说了，传送门：Web 页面优化专项 > Lighthouse > 性能分数优化。后面买了些小册，试了试手法。基本都是微调、合理性研究。
- 
流程编排。今年做了三个相关的平台，可给我累坏了
流程中心。主要是平台能力开发，业务流转，串并竞催办撤销等等
  比较爽的是将接入方式做了升级，用了一些内部平台支持自助接入（编码、异步组件、Pro-Code、Low-Code、配置化、No-Code），将接入效率提升一个层次（然后就不需要我就这个码农了，所以我走了？  (⊙_⊙)?）
  首次接入（ x天 => 1小时），小变更（0.5天 => 5分钟），并且平台和业务互相解耦，稳定性 MAX
- API 编排。类似于 n8n、node-red 吧，当然参考了业界，比如说阿里云、百度云、宜搭等等一些 API 编排的工具。我们操作的资源是 GraphQL-Mesh 中聚合的数据源。自研了几个编辑器（串、树、图）用来内部测试
- 流水线（CI）。我工作主要也是提供平台的能力，这块没啥功劳，苦劳比较多吧（3个Q的需求，一个Q补完）
- 
做了一些体验性的优化。好多业务其实都是相通的，虽然没做过，但是套过来也能用。我还遇到很多很多 BUG，可惜没记录下来（但是我会修）
`this.$on('hook:beforeDestroy')` 触发不稳定，需要使用 `beforeDestroy` 前面是屁话，没用，需要关注的是别有 await
