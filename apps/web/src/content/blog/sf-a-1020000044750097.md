### 解答思路
先了解两种常见方案各自的优缺点，再结合临时授权 URL 弥补它们的短板，最终得到一个兼顾安全性、移动端兼容性和后台下载能力的方案。

### 详细说明
- **方案一：Blob + `createObjectURL`**
  1. 请求时设置 `responseType: 'blob'`，在 Ajax 回调里直接拿到 `Blob` 对象；
  2. 用 `URL.createObjectURL(blob)` 生成一个临时的 blob URL；
  3. 创建一个 `<a>` 标签，设置 `href` 为该 blob URL，并设置 `download` 属性触发浏览器下载。
  - **缺点**：不支持移动端（部分移动浏览器对 blob URL 下载支持不佳），且必须保持页面一直打开才能完成下载，不支持真正的后台下载。
- **方案二：`<form target>` 触发浏览器默认下载**
  - 直接构造一个表单并提交（或跳转到下载地址），利用浏览器原生的下载能力，天然支持移动端和后台下载。
  - **缺点**：无法携带自定义请求头（headers），因此不能直接用于需要鉴权 header 的接口。
- **解决 headers 限制：改用临时授权 URL**
  - 后端提供一个接口，先用正常的鉴权请求（可带 headers）换取一个临时授权下载链接（通常带有效期短的 token 作为 URL 参数）；
  - 前端拿到这个临时 URL 后，直接通过方案二（`<form target>` 或跳转）下载，因为鉴权信息已经内嵌在 URL 中，不再需要 headers。

### 小结
纯前端 Blob 方案适合桌面端、页面常驻的场景，但移动端兼容性和后台下载能力不足；改用 `<form target>` + 临时授权 URL 的组合方案，既能绕开无法携带 headers 的限制，又能获得移动端友好、支持后台下载的完整下载体验，是更通用的做法。
