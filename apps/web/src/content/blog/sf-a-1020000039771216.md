### 解答思路
浏览器层面无法真正“禁止”任意 JS 修改 DOM——只要脚本能拿到节点引用，就可以对其进行任意操作，这是浏览器开放能力决定的，无法从根本上阻止。可行的思路是转为**监听 + 恢复**，而不是**阻止**。

### 详细说明
- 直接阻止：做不到，任何运行在页面上下文中的脚本理论上都能操作 DOM。
- 可行的替代方案：
  1. **备份 + 恢复**：提前 `cloneNode` 备份关键 DOM 结构，一旦发现被删除/篡改，就用备份的克隆节点还原。
  2. **实时监听**：使用 `MutationObserver` 监听目标节点及其子树的变化，一旦检测到节点被移除，就触发回调进行处理（告警、恢复、去重等）。

### 示例代码
```js
const observer = new MutationObserver((mutations) => {
  for (const mutation of mutations) {
    if (mutation.removedNodes.length > 0) {
      console.warn('检测到节点被移除:', mutation.removedNodes);
      // 这里可以做恢复逻辑，例如重新插入备份的克隆节点
    }
  }
});

observer.observe(document.body, { childList: true, subtree: true });
```

### 小结
无法从根本上“禁止”JS 删除 DOM，但可以通过 `MutationObserver` 实时监听变化，结合提前克隆备份的节点，在检测到删除后进行恢复或告警。
