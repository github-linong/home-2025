### 解答思路
通过 DOM class 特征判断出目标元素是 [Semi Design](https://github.com/DouyinFE/semi-design) 的 `Dropdown` 组件；再通过阅读该组件的单元测试和源码，确认它本质上是基于 `Tooltip` 组件实现弹出展示的，进而找到通过 `ref` 调用内部 Foundation 方法来主动触发显示的思路。

### 示例代码（如有代码）
参考 Semi Design 官方单元测试中的触发方式（[dropdown.test.js](https://github.com/DouyinFE/semi-design/blob/main/packages/semi-ui/dropdown/__test__/dropdown.test.js)）：

```js
it('Dropdown-trigger-hover', async () => {
  const props = { trigger: 'hover' };
  const dropdown = getDD(props);

  // hover 之前，下拉内容未展示
  expect(dropdown.exists(el_portal_inner)).toEqual(false);

  // 触发 hover 后，下拉内容展示
  dropdown.find(`.${BASE_CLASS_PREFIX}-tag`).simulate('mouseEnter', {});
  expect(dropdown.exists(el_portal_inner)).toEqual(true);
  expect(dropdown.find(el_item)).toHaveLength(3);

  await sleep(1000);

  // 移出后自动隐藏
  dropdown.find(`.${BASE_CLASS_PREFIX}-tag`).simulate('mouseLeave', {});
  await sleep(1000);
  expect(dropdown.exists(el_portal_inner)).toEqual(false);
  expect(dropdown.find(el_item)).toHaveLength(0);
});

it('Dropdown-trigger-click', () => {
  const props = { trigger: 'click' };
  const dropdown = getDD(props);

  expect(dropdown.exists(el_portal_inner)).toEqual(false);
  expect(dropdown.exists(el_item)).toEqual(false);

  dropdown.find(`.${BASE_CLASS_PREFIX}-tag`).simulate('click', {});
  expect(dropdown.exists(el_portal_inner)).toEqual(true);
  expect(dropdown.find(el_item)).toHaveLength(3);
});
```

### 详细说明
- **定位组件来源**：通过目标元素的 class 前缀，判断出这是 Semi Design 的 `Dropdown` 组件，随后直接去官方仓库查阅对应的单元测试和源码（[`dropdown/index.tsx`](https://github.com/DouyinFE/semi-design/blob/658b28361f0737df59519e08a669455944c8b93b/packages/semi-ui/dropdown/index.tsx#L237)）。
- **`Dropdown` 与 `Tooltip` 的关系**：
  - `Dropdown` 的渲染输出中直接使用了 `Tooltip` 组件，把内部生成的下拉内容（`renderContent()`）作为 `Tooltip` 的 `content` 属性传入；
  - `DropdownProps` 类型继承自 `TooltipProps`，因此很多控制弹出行为的配置项（`position`、`trigger`、`spacing`、`closeOnEsc`、`onEscKeyDown`、`zIndex` 等）实际上都是转发给 `Tooltip` 使用的；
  - `Dropdown` 内部持有一个 `Tooltip` 的 `ref`（`this.tooltipRef`），用于获取弹出层 id，并通过 Foundation adapter 通知/控制显示状态。
- **Foundation 模式**：`Dropdown` 自身使用 Foundation（业务逻辑层）处理可见性、键盘交互等逻辑，UI 展现则完全交给 `Tooltip` 负责弹出定位与动画，这是 Semi Design 组件库常见的架构分层方式（Foundation 负责逻辑，UI 层负责渲染，方便跨端复用逻辑）。
- **hover/focus 触发机制**：通过在触发元素上绑定 `mouseEnter`/`mouseLeave`（以及 `focus`/`blur`）事件，触发后调用 Foundation 的 `delayShow`/`delayHide`（基于 `mouseEnterDelay`/`mouseLeaveDelay` 的定时器）实现延迟显示/隐藏，最终调用 `show`/`hide` 完成弹出层（Portal）的插入与销毁，期间还有一些竞态保护逻辑（比如插入后再次确认鼠标是否仍处于 hover 状态）。
- **代码层面主动触发的思路**：既然显示/隐藏最终由 Foundation 的 `delayShow`/`hide` 控制，理论上可以通过组件的 `ref` 拿到 `tooltipRef`，进而调用底层 Foundation 暴露的方法（如 `delayShow()`），并对其原本会自动调用的 `hide()` 进行拦截/劫持，从而实现代码层面主动、可控地触发下拉显示，而不依赖真实的鼠标事件。

### 小结
Semi Design 的 `Dropdown` 本质上是基于 `Tooltip` 实现弹出展示的封装组件，触发逻辑由 Foundation 层的 `delayShow`/`hide` 控制。要在代码层面（而非真实鼠标操作）触发其显示，思路是通过组件 `ref` 访问内部 Foundation 方法并主动调用/拦截，具体的完整实现代码在原始资料中被截断，实现时需要结合源码进一步补全。
