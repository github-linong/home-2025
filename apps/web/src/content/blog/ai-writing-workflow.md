## 为什么用 AI 写博客

写技术博客最难的不是写，而是：

1. 开始写（对着空白文档发呆 30 分钟）
2. 组织结构（想到哪写到哪，逻辑混乱）
3. 坚持写完（写了一半放弃）

AI 不能替代你的思考，但能帮你：

- 快速生成大纲
- 补充遗漏的点
- 润色文字表达
- 检查错别字

## 我的工作流

### 第 1 步：选题

来源：

- 最近踩的坑（最有价值）
- 刚学会的新技能
- 工作中的解决方案
- 读者提问

AI 辅助：

```
我最近用 Next.js 16 做了个静态站，踩了不少坑。
帮我想 5 个有吸引力的标题，要包含关键词"Next.js 16"和"踩坑"。
```

### 第 2 步：大纲

AI Prompt：

```
我要写一篇关于"Next.js 16 Static Export 踩坑"的技术文章。
读者是前端开发者，有 Next.js 基础。

帮我生成一个详细大纲，包括：
1. 背景介绍
2. 遇到的 3-5 个主要问题
3. 每个问题的解决方案
4. 总结

要求：每个问题要有代码示例的位置标记。
```

输出示例：

```
## 背景
- 为什么选择 Static Export
- 项目需求

## 坑 1：sitemap.ts 不兼容 export
- 错误信息
- 原因分析
- 解决方案

## 坑 2：Google Fonts 国内不可用
...
```

### 第 3 步：初稿

我的做法：

1. 按照大纲，每个小节自己写
2. 遇到卡壳的地方，问 AI
3. 代码示例自己写（AI 写的代码要仔细检查）

AI 辅助场景：

```
这一段我想解释"为什么 Static Export 不支持 Route Handlers"，
但我写得有点啰嗦，帮我简化一下，保持技术准确性。
```

### 第 4 步：润色

AI Prompt：

```
帮我检查这篇文章：
1. 有没有错别字
2. 有没有语句不通顺的地方
3. 有没有更好的表达方式
4. 技术术语使用是否准确

不要改变我的写作风格，只做必要的修改。
```

### 第 5 步：配图

工具：

- Excalidraw（手绘风格图表）
- 截图 + 标注（CleanShot X）
- AI 生成（如果需要）

### 第 6 步：发布

检查清单：

- 标题有吸引力
- 描述简洁明了（SEO）
- 标签合理（3-5 个）
- 代码高亮正常
- 链接都有效
- 移动端显示正常

## 保持个人风格

关键：AI 是助手，不是代笔。

我的原则：

1. 观点自己提（AI 没有真实经验）
2. 代码自己写（AI 写的要逐行检查）
3. 例子自己举（AI 的例子太通用）
4. 语气自己定（保持你的说话方式）

AI 适合做的：

- 生成大纲
- 补充遗漏点
- 润色文字
- 检查错误

AI 不适合做的：

- 代替思考
- 生成代码（不检查直接用）
- 创造观点
- 模仿你的风格

1. 选题：我自己定的（写 AI 写作流程）

3. 初稿：我自己写

## 总结

AI 写博客的正确姿势：

**你负责思考，AI 负责辅助。**

不要指望 AI 一键生成高质量文章，但善用 AI 可以让你：

- 写得更快
- 写得更清楚
- 坚持写下去
