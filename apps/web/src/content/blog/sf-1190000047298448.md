在 ModalForm 组件中，request 属性用于异步加载表单数据，而 destroyOnClose 属性在关闭时销毁表单。当表单数据尚未加载完成时，关闭表单会导致 form 实例被销毁，从而在调用 resetFields 方法时抛出错误。

#### 简要对齐
- 你的 Issue 链接指出：ModalForm 同时使用 `formRef`、`request` 与关闭销毁时（`destroyOnHidden`/`destroyOnClose`），在加载中关闭会报错 “form.resetFields is not a function”。
- 代码走查显示，项目内部统一使用 `destroyOnHidden`（非 antd 原生的 destroyOnClose）控制关闭时销毁。风险点在于关闭时 `form` 实例可能尚未就绪或已被销毁，从而直接调用 `resetFields` 报错。
- 目标：最小化修复，保证兼容、不引入依赖、通过全部测试。

#### 最小修复点（代码 diff）
- 在 `ModalForm` 与 `DrawerForm` 的关闭重置逻辑里，为 `resetFields` 增加安全存在性检查，避免在 `form` 尚未初始化或已销毁时调用。

代码引用：

```
  const resetFields = useCallback(() => {
    const form = rest.form ?? rest.formRef?.current ?? formRef.current;
    // 重置表单
    if (modalProps?.destroyOnHidden && form && typeof (form as any).resetFields === 'function') {
      (form as any).resetFields();
    }
  }, [modalProps?.destroyOnHidden, rest.form, rest.formRef]);
```

  const resetFields = useCallback(() => {
    const form = rest.formRef?.current ?? rest.form ?? formRef.current;

#### 解决思路对比与选择
- 方案A：在关闭时调用 `resetFields` 前做方法存在性检查（已选）。最小改动、兼容性好。
- 方案B：在 `BaseForm` 请求完成后再触发重置。副作用大，改变行为时机，风险高。
