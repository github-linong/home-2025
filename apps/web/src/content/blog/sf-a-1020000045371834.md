### 解答思路
两者并不是完全互斥的关系：`axios` 是更底层的 HTTP 客户端，负责发请求本身；`React Query` 是更高层的数据请求管理库，负责请求状态（加载中/成功/失败）、缓存、重试等能力，实际项目中也可以搭配使用（用 `axios` 发请求，用 `React Query` 管理请求状态）。

### 详细说明
- **`axios`**：一个基于 Promise 的 HTTP 客户端，可用于浏览器和 Node.js。支持请求/响应拦截器、请求与响应数据转换等特性，更加原始，可以按需自己实现各种拦截器逻辑，定制自由度高。
- **`React Query`**：专为 React 设计的数据查询库，提供缓存、状态同步、分页、自动重试等高级功能。它不仅负责发请求，还统一管理请求的各种状态（加载中、成功、失败），让组件中展示这些状态变得更简单，减少手写 loading/error 状态的样板代码。
- **实际使用中遇到的问题**：
  - 使用 `axios` 时，曾在 Node.js 环境下遇到请求异常丢失的问题，最终通过社区提供的一个包解决。
  - 使用 `React Query` 时，曾在弱网环境下遇到请求丢失的问题，通过调整判断逻辑解决。
  - 这说明无论选哪个方案，都可能遇到边界场景的坑，关键是遇到问题时能定位并有对应的解决办法。
- **如何选择**：如果偏好自己掌控请求细节、拦截器逻辑，倾向于用 `axios`（也可以搭配社区的缓存插件补齐能力）；如果希望减少请求状态管理的样板代码，直接获得缓存、重试、分页等能力，`React Query` 会更省心。也可以两者结合：用 `axios` 作为底层请求实现，用 `React Query` 做上层的状态与缓存管理。

### 小结
`axios` 和 `React Query` 并非二选一，而是分别处于请求实现和请求状态管理两个层次，可以单独使用也可以组合使用。选择哪种取决于项目对自定义拦截器、缓存能力、状态管理便利性等方面的具体需求。
