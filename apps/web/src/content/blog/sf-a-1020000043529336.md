### 解答思路
先明确问题出在前端还是后端，再对照参数名是否一致，最后确认请求的 `Content-Type` 是否支持文件上传。

### 示例代码（如有代码）
```java
@PostMapping("/upload")
public void upload(@RequestParam("avatar") MultipartFile file, @RequestParam("id") int id) {
    // ...
}
```

### 详细说明
- **排查顺序**：
  1. 前端打开浏览器 Network 面板，确认请求是否正确携带了文件字段。
  2. 后端用 Postman 之类的工具直接模拟同样的请求，验证接口本身能否正常接收文件。
  3. 如果两端各自测试都正常，问题往往出在字段名不一致：比如前端传的字段名是 `file`，但后端 `@RequestParam` 写的是 `avatar`，两者必须完全对应。
- **`params` 与 `body` 的区别**：`@RequestParam` 默认从请求参数（类似 GET 的 query 参数）中取值，而文件上传需要放在请求体（`body`）中，以 `multipart/form-data` 的形式提交。
- **常见的 `Content-Type` 对比**：
  - `application/json`：不支持文件上传。
  - `multipart/form-data`：支持文件上传，也是文件上传的标准方式（Base64 字符串等间接方案不算真正的文件上传）。
  - `application/x-www-form-urlencoded`：不支持文件上传。

### 小结
文件传到后端为 `null`，多数情况是参数名不匹配或 `Content-Type` 用错导致的。建议先用 Network / Postman 分别定位是前端还是后端的问题，再核对字段名和 `Content-Type` 是否为 `multipart/form-data`。
