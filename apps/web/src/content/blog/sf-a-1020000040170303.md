### 解答思路
`devServer.proxy` **只在本地开发服务器下生效**，本质上是本地 Node 服务帮你转发请求，从而绕开浏览器的跨域限制；打包上线之后，代码是静态文件，没有这个开发服务器在跑，代理自然失效。所以要先确认「代理无效」到底发生在开发环境还是生产环境。

### 详细说明
- **开发环境**：如果配置类似
  ```js
  devServer: {
    proxy: {
      '/api': {
        target: 'https://geo.datav.aliyun.com',
        changeOrigin: true,
      },
    },
  },
  ```
  请求路径写成 `/api/areas_v2/bound/geojson?code=100000`，理论上应该生效。如果没生效，先检查浏览器请求的 `Host` 是否显示为 `localhost`——如果是，说明请求确实先打到了本地 Node 服务再转发；如果 `Host` 直接就是目标域名，说明代理配置没有被真正应用（可能是路径前缀不匹配，或代理配置层级放错了）。
- **生产环境**：静态资源部署后不存在开发代理服务，跨域问题需要用 Nginx（或其他反向代理网关）在服务器层做代理转发。
- **排查建议**：可以先把 `target` 换成一个自己完全可控、明确知道行为的接口，确认代理链路本身是否通畅，再排查目标接口是否有特殊限制（如校验 `Referer`、`Origin`）。

### 小结
`devServer.proxy` 只是开发期方案，上线后必须依赖 Nginx 等服务端代理来解决跨域；排查时先确认问题出在开发环境还是生产环境。
