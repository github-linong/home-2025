### 解答思路
`localStorage` 本身不是响应式的，但浏览器提供了 `storage` 事件：当某个页面修改了 `localStorage`，其他同源的页面可以通过监听 `window` 的 `storage` 事件感知到变化，从而实现一种准响应式的跨页面同步。

### 示例代码（如有代码）
```js
// 页面 A：写入数据时同步更新 Vuex 与 localStorage
store.commit('setData', newValue);
localStorage.setItem('sharedData', JSON.stringify(newValue));

// 页面 B：监听 storage 事件，感知其他页面的修改
window.addEventListener('storage', (e) => {
  if (e.key === 'sharedData') {
    store.commit('setData', JSON.parse(e.newValue));
  }
});
```

### 详细说明
- `storage` 事件只会在其他页面（非当前发起修改的页面）触发，当前页面自己修改 `localStorage` 不会触发自身的 `storage` 事件，这一点在设计同步逻辑时需要注意。
- 常见做法是：每次修改数据时，同时写入 Vuex（用于当前页面的响应式更新）和 `localStorage`（用于跨页面广播）；其他页面监听到 `storage` 事件后，再把最新值同步写回自己的 Vuex，驱动页面响应式更新。
- 这种方案存在一定的体验局限：`storage` 事件依赖浏览器触发，会有一定延迟，且数据结构较复杂时需要频繁 `JSON.stringify` / `JSON.parse`，如果对实时性要求很高，可以考虑 `BroadcastChannel` 或 `SharedWorker` 等更专门的跨页面通信方案。

### 小结
`localStorage` 配合 `window` 的 `storage` 事件，可以实现跨页面的数据同步，思路是本地修改时写 Vuex + 写 storage，其他页面监听 storage 事件再同步回 Vuex，但体验上存在延迟等局限，对实时性要求高的场景可以考虑更专门的跨页面通信 API。
